# 田 트랙 지도 기반 주행 제약 — 오프라인 통합용 초안

이 폴더만 새로 만들었습니다. Raspberry Pi 접속·배포·GPIO·모터 제어는 하지 않습니다.
클로드의 카메라/라인트레이싱 코드에 붙일 수 있는 별도 판단 모듈이며, 완성된 실차 자율주행 프로그램은 아닙니다.

## 사용자에게서 확인된 치수와 미측정값

2026-10-30 추가 실측 반영: 차량 전체 길이 0.26m, 바퀴 포함 폭 0.155m. 길이는 축간거리가 아닙니다.
사진 기준 왼쪽 외곽 도로 0.26m, 아래 외곽 0.24m, 내부 세로 0.18m, 내부 가로 0.21m.
구간별 국소 측정값이며 위/오른쪽 도로 폭이나 구간 전체 최소 폭은 아직 확정하지 않았습니다.
기존의 '모든 외곽 26cm, 내부 모두 18cm, 차량 폭 16cm' 가정은 실차 설정에서 폐기했습니다.
`measurements.photo.json`은 사진의 133/129/37/32/12cm 표시도 보존합니다. 전체 크기나 코너 반지름으로 자동 환산하지 않습니다.
`config.real.json`의 나머지 값은 미측정(null)으로 유지했습니다. 사진은 원근이 있는 참고 자료이며 실제 치수 지도로 변환하지 않았습니다.
전체 트랙 크기, 섬/코너의 곡선 경계, 카메라-차량 기준점 관계, 지연, 최악 제동거리, 미끄러짐 오차가 추가로 필요합니다.

`demo.py`의 1.8m 정사각형과 차량 길이 0.22m는 작동 확인을 위한 가상값입니다. 실제 트랙 치수로 사용하지 마세요.
모형은 반듯한 사각 고리와 십자 합집합이며 실제 사진의 둥근 코너/섬 경계를 표현하지 않습니다.

## 구현 범위

* `TianGraph`: 9개 노드, 12개 도로 구간. 진입 방향에 따라 직진/좌회전/우회전 가능 집합 계산. 유턴은 기본 제외.
* `PoseFilter`: 속도·각속도 예측과 카메라 절대 위치 측정으로 x,y,yaw 갱신. 측정 시각·이상치 검사. 명령 속도는 엔코더 측정이 아니므로 오차를 크게 잡아야 합니다.
* `ground_points`: 왜곡 보정된 영상의 바닥 점을 실측 호모그래피로 차량 기준 미터 좌표에 투영.
* `pose_from_landmarks`: ID가 알려진 바닥 랜드마크 3개 이상으로 차량 위치/방향 추정. 대응점 오차 검사. ID 자동 인식은 구현하지 않았습니다.
* `vision.yellow_boundary_candidates`: 노란 경계 후보 픽셀 추출과 바닥 투영. 바닥 ROI·H 필수. 색상만으로 경계를 확정하지 않으며, 실제 프레임 검증 전입니다.
* `Supervisor`: 영상 유실, 위치 모호성, 금지 회전, 미측정 지도, 정지 경로 부족을 거부. 차량 전체 다각형과 오차 여유를 도로 마스크에 대조.

## 좌표와 교차로

세계 좌표는 x=오른쪽/동쪽, y=위쪽/북쪽, yaw=동쪽에서 반시계 방향 라디안, 단위 m입니다.
차량 pose는 바퀴축이 아닌 **전체 외곽 사각형 중심**입니다. 다른 기준점의 추정 결과는 반드시 변환해야 합니다.
마스크 좌표는 `(column * resolution, row * resolution)`입니다. 따라서 일반 지도 PNG의 위쪽이 북쪽이면 로딩 시 상하 반전해야 합니다.
도로폭이 선 안쪽 사이인지 선 중심 사이인지 명확히 측정하고, 마스크는 실제 허용 영역을 보수적으로 나타내야 합니다.

```text
02 ── 12 ── 22
│     │     │
01 ── 11 ── 21
│     │     │
00 ── 10 ── 20
```

`00 → 10`으로 접근하면 직진 `20`과 좌회전 `11`만 가능합니다. 우회전은 지도상 도로가 없어서 거부합니다.
`20 → 10`이면 직진/우회전입니다. 같은 교차로라도 진입 방향을 반드시 알아야 합니다.
지도에 물리적 도로가 있더라도 일방통행·표지판·대회 규칙 때문에 금지될 수 있습니다. 그런 규칙은 별도 허용 집합과 교집합해야 합니다.

## 클로드 코드에 붙이는 순서

1. 시작 노드/구간, 위치, 방향을 지정합니다. 재부팅 후 예전 위치를 그대로 복원하지 않습니다.
2. 렌즈 왜곡 보정 후, 그 출력 좌표계에서 새로 구한 바닥 호모그래피를 사용합니다. 원본 영상용 H를 보정 영상에 섞어 쓰면 안 됩니다.
3. 실측 속도 또는 오차를 충분히 포함한 명령 속도로 `PoseFilter.predict`를 호출합니다. 카메라 획득 시각은 단조 시계이며 now와 같은 시간축이어야 합니다.
4. 고유 랜드마크 또는 신뢰 가능한 지도 정합으로 카메라 pose/covariance를 만들고 `update_camera`를 호출합니다. 입력은 사실상 현재 시각과 정렬해야 합니다. 지연 보상 EKF는 구현하지 않았으므로 오래된 프레임은 거부합니다.
5. 지도와 영상이 일치하는 진입 구간 후보를 유지합니다. 후보가 둘 이상이면 정지하고 재위치추정합니다. 이 대칭 지도에서 단일 EKF가 자기 위치를 전역적으로 알아내지는 못합니다.
6. `TianGraph.exits(previous,junction)`로 가능한 다음 노드를 정하고, **그 선택에 실제로 대응하는** 조향 궤적을 생성합니다. 경로 플래너/진입 구간 자동 전이/차동구동 모델은 클로드 코드 담당입니다.
7. 현재 상태부터 제어 지연 구간, 예정 동작, 완전 제동까지 포함한 `Sample` 목록을 `Supervisor.evaluate`에 넘깁니다. 정지까지의 전체 추적 오차 상한을 `tracking_error_bound`로 제공합니다.
8. 거부 결과는 정지 명령으로 처리하고, 통과 결과만 실제 모터 출력 직전에 반영합니다. 프레임/판단 결과 유효기간도 출력 직전에 다시 검사합니다. 이 코드 자체에는 모터 출력이 없습니다.

`turn` 문자열만 바꾸고 실제 궤적은 다른 쪽으로 보내는 잘못된 어댑터는 방어하지 않습니다. 진입 구간·선택한 출구·궤적의 일치성을 플래너에서 보장해야 합니다.
정지 궤적은 단순한 임의 점열이 아니라 실제 제동 실험과 운동 모델로 생성해야 합니다. 최소 길이/마지막 속도 검사는 물리적 정확성 검증을 대신하지 않습니다.
검사하는 보간은 위치/yaw의 선형 보간이며 그 사이를 보수적인 팽창으로 덮습니다. 실차가 그 보간을 벗어나는 오차를 별도 상한에 포함해야 합니다.

실제 지도는 `RoadMask(mask, resolution_m_per_pixel, measured=True)`로 연결합니다. `measured=True`는 자동 측정 검증이 아니라 통합자의 선언입니다.
`simulation=True`는 데모/테스트 전용이며 실차에서는 사용하지 마세요. 실제 설정 파일은 자동 로딩/주행 실행을 제공하지 않습니다.

## 18cm 도로의 오차 예산

차가 평행하고 중심에 있을 때 좌우 여유는 내부 세로 도로에서 각각 `(18-15.5)/2 = 1.25cm`, 내부 가로 도로에서는 `(21-15.5)/2 = 2.75cm`입니다.
직선 구간에서 아래 조건이 필요합니다(직사각형 차량 근사):

`W * |cos(yaw_error)| + L * |sin(yaw_error)| + 2*(lateral_error + margin) <= road_width`

따라서 차 길이가 길수록 작은 방향 오차도 여유를 빠르게 소비합니다. **실측 길이 26cm, 폭 15.5cm**에서 방향 오차 5도이면 횡방향 투영 폭은 약 17.71cm입니다. 18cm 직선 도로에서는 중심이 정확해도 한쪽 여유가 약 1.46mm만 남습니다.
`python clearance.py`는 실측 설정을 읽어 0/3/5/10도 정적 여유와 최초 경계 접촉 각도를 `output/clearance.real.json`에 계산합니다. 이 각도는 오차·지연·안전 여유가 없는 접촉 한계이며 실차 허용각으로 사용하면 안 됩니다.
현재 감독기는 위치 3σ, 방향 3σ에 따른 외곽 변위, 실측 추적 오차, 사용자 여유, 격자 오차를 합칩니다. 3σ는 통계적 여유이며 절대 보장이 아닙니다.
코너 회전은 정지 회전도 차량 모서리가 도로 밖으로 나갈 수 있으므로 차량 전체 회전 공간을 검사해야 합니다.

카메라를 잃거나 위치가 불확실해진 뒤 멈추는 경우에도 관성과 지연 동안 이동합니다. 그래서 검증 경로는 항상 완전 정지까지 포함해야 합니다.
커맨드만으로 추정한 위치는 바퀴 미끄러짐/배터리 변동으로 누적 오차가 커집니다. 차선 영상은 횡방향 위치를 알려줄 수 있지만 긴 직선에서 진행 거리까지 고유하게 정하지 못합니다.
반복되는 횡단보도 무늬를 서로 다른 고유 위치 표식으로 취급하지 마세요. 허용된다면 고유한 바닥 마커가 대칭성 해소에 유용합니다.

## 실행 및 검증

```powershell
python -m unittest -v test_guard
python demo.py
```

이 폴더에서 실행합니다. `output/topology_demo.png`와 `output/demo_results.json`이 생성됩니다.
실차 검증은 하지 않았습니다. 코드 테스트는 금지 우회전, 진입 방향별 회전, 위치 모호성, 1cm 횡이동, 방향 오차, 오래된 카메라, 정지 거리 부족, 차량 아래 섬, 랜드마크 오정합을 포함합니다.
측정과 통합 이후에도 바퀴를 들고 금지 회전/카메라 유실/재시작을 확인하고, 저속 트랙 시험에서 실제 추적·제동 오차를 구해야 합니다.
