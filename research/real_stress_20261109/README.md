# 실차 기록에서 출발한 환경 간섭 시험 · 2026-11-09

질문은 **이전의 작은 운동 오차를 극복한 시뮬레이터에 실차에서 문제였던 조건을 넣으면, 실차와 비슷한 정지가 생기는가**이다. Raspberry Pi에 접속하거나 주행 코드를 배포하지 않았다. 원래 제어기 파일을 수정하지 않고 별도 실험 하네스에서 실행했다.

## 무엇을 고정했나

`Feedback + FixedGain`, 색 임계값 V135, `photo_plus5mm_rim.npy`, 여유거리 한도 0.25cm, 640×480 보정 영상, 15Hz를 사용했다. 출력계수는 기존 Feedback 로직으로 바뀌지만 운동 예측 회전계수는 고정이다. 둘 모두 동적으로 갱신한 실험으로 부르면 안 된다. 명령 모델은 `16cm/s × 평균 PWM`이며 전진 예측 배율은 1이다.

**11월 6일의 마지막 forward127 배포본과 동일한 실행판은 아니다.** 마지막 배포본은 특정 직진 명령 조건에서만 예측 배율 1.27을 썼다. 이번 폐루프 대조군은 그 직전 V135 설정과 같은 기본 구조다. 마지막 배포본의 저장 관측점은 별도의 오프라인 후보 탐색에 포함했다.

기본 차량 응답은 기록의 좌회전 약 0.69324, 별도 시계 방향 기록 두 번째 코너의 우회전 약 0.63170이다. 제어기 우회전 사전값은 첫 번째 코너의 약 0.62173을 사용한다. 차량 기준점은 차체 중심보다 2.25cm 뒤다. 실제 및 예측 여유는 같은 사진 윤곽으로 채점한다. 예전 직사각형 윤곽을 쓴 실험의 최소 여유와 직접 비교하지 않는다.

시뮬레이터 정답은 렌더링·교란 주입·사후 채점에만 쓴다. 제어기에는 변형된 영상과 자신이 보낸 명령만 전달한다. 결과의 `simulated_laps`는 맵 원점 주변 누적 각도로 계산한 진행도이고, 성공 종료 판정은 제어기의 경로 길이 진행도이다. 둘을 함께 기록했다.

## 실측과 가정의 경계

| 조건 | 근거 | 이번 구현과 한계 |
|---|---|---|
| 긴 노출 | 정지 버퍼 metadata 약 49.972/66.513ms | 66.513ms 노출 구간의 위치 3곳을 렌더링해 평균. 4초간 적용. 센서 노이즈·rolling shutter·렌즈 산란까지 재현한 것은 아님 |
| 회전 응답 변화 | 다른 코너에서 좌회전 약 0.693 → 0.645 | 4초간 반응 감소. 전진 1.27배, 왼쪽 쏠림 −1°/s도 함께 넣은 구동 묶음. 쏠림 수치는 실측 아님 |
| 전진 배율 | 직진 실측 뒤 1.27을 검토한 기록 | 실제 속도만 예측보다 27% 빠른 상태를 2초부터 지속. 모든 PWM/노면에 대한 실측 모델이라는 뜻이 아님 |
| 트랙 이음새 | 실제 두 판의 경계를 붙인 뒤 통과했다는 사용자 관찰 | 도로와 초록 영역을 가로지르는 폭 1cm 어두운 띠. 시작 시 차량 앞 20cm 지점에 배치, 이후 계속 남음. 실제 틈 폭·절대 위치의 복제는 아님 |
| 반사 | 실제 사진에 큰 밝기·색 변화 존재 | 화면상의 타원형 밝기 혼합. 크기·강도는 감도 시험 가정, 실차 반사계수 측정 아님 |
| 그림자 | 시연 환경에서 예상한 위험 | 화면 좌측을 부드럽게 어둡게 함. 시연장 측정자료 없음 |
| 물체 가림 | 트랙 위 표지판·시설물 존재 | 화면의 녹색/황색 사각형 물체를 그려 바닥 외 특징을 투입. 실제 물체의 3D 위치·메시 재구성 아님 |
| 바퀴 지연 | 바닥에서 왼쪽 뒷바퀴 2~3초 지연 관찰 | 2초간 좌측 등가 속도 50%로 줄이는 강한 대리 시험. 바퀴 하나 정지가 좌측 속도 반감이라는 물리 법칙은 아님 |
| 잘못된 prior | 실제 자세 오차의 독립 정답 없음 | 추정기에 오차를 직접 넣는 진단 대조군. 실측 미끄러짐 크기로 보고하면 안 됨 |

노출·반사·그림자·물체는 기본 20~24초 구간에 적용했다. 서로 다른 방향은 그 시각의 위치와 보이는 경계가 다르다. 따라서 방향별 결과 차이는 **해당 경로·시야·교란 조합의 차이**이며 모터의 방향별 성능을 분리해 측정한 값이 아니다. 결정론적 제한 시나리오이며 성공률 통계나 모든 환경에 대한 보장은 아니다.

## 후보 탐색

실제 저장된 `points`, `prior`, `residual_cm`을 사용했다. 맵으로 재계산한 원래 잔차가 저장값과 1e-5cm 이내로 같은지 먼저 검사했다. 참고 수동 선이나 CNN 예측점으로 바꾸지 않았다.

- prior 차체 좌표에서 횡방향 −3~+3cm (0.5cm), 종방향 −8~+8cm (0.5cm), yaw −6~+6° (1°): 총 5,577개.
- 순위 점수: 모든 점에 대해 `mean(min(abs(SDF), 5cm)^2)`. 이상점도 고정 비용으로 남긴다.
- 기존 게이트: 중앙값 ≤1.8cm, 2.5cm 미만 점 비율 ≥55%.
- 최저 비용 후보, 게이트를 통과하는 최저 비용 후보, 통과 수·범위를 따로 기록한다. 비용 최저와 게이트 통과는 같지 않을 수 있다.
- 24장씩의 검사는 각 장의 **기록된 prior를 따로** 검색한 것이다. 새 자세로 명령을 다시 보내는 실차 폐루프 재생도, 연속 최적화도 아니다.
- 통과 후보가 있다는 것만으로 정확한 자세 또는 정상 관측임을 판정하지 않는다. 탐색 범위 밖의 정답, 잘못된 경계, 여러 자세가 만드는 유사 영상을 고려해야 한다.

## 재현

저장소 루트에서 Python 3.11, NumPy 2.4.6, OpenCV 4.14.0으로 실행했다. 하드웨어 라이브러리 설치나 Pi 접속은 필요 없다. 영상 묶음 변환에만 ffmpeg가 필요하다.

```powershell
python research/real_stress_20261109/experiment.py grid
python research/real_stress_20261109/temporal_grid.py

# 기본 8조건, 양방향. 'all'에는 추가 진단 조건도 포함되므로 목록을 명시한다.
foreach ($direction in @('ccw','cw')) {
  foreach ($case in @('clean','response_only','exposure_66ms','glare','shadow','seam','object','combined')) {
    python research/real_stress_20261109/experiment.py sim --direction $direction --scenario $case --video
  }
  python research/real_stress_20261109/experiment.py sim --direction $direction --scenario forward_persistent --onset 2 --video
  python research/real_stress_20261109/experiment.py sim --direction $direction --scenario stall_combined --video
}
python research/real_stress_20261109/experiment.py sim --direction ccw --scenario prior_error --video
python research/real_stress_20261109/experiment.py sim --direction ccw --scenario prior_lateral --video
python research/real_stress_20261109/audit_stops.py
python research/real_stress_20261109/render_review.py
python research/real_stress_20261109/build_report.py
python research/real_stress_20261109/verify_results.py
```

개별 원본 영상은 교란 전 2초~후 10초를 발췌하고 마지막 상태를 붙인다. 마지막 시각으로 건너뛰는 편집이 있으며 화면의 `t`를 확인한다. 별도 `*_review.mp4` 및 `comparison.mp4`는 저장된 시뮬레이션 자세로 **정지 직전 6초를 다시 렌더링**했다. 깨끗한 대조군만 20~26초를 보여 준다. 새 제어 시험을 한 것은 아니다. 비교 영상의 각 패널은 자기 시간 표시를 유지하므로 패널끼리 같은 절대 시각이 아니다. 먼저 끝난 시험은 마지막 화면을 유지한다. 초록 윤곽은 실제 모의 자세, 자홍 윤곽은 제어기 추정 자세다. Git에는 코드·수치·합성 미리보기를 보관하고 큰 영상은 로컬 산출물로 둔다.

## 포함하지 않은 것

실제 광학·조명·모터 토크를 식별한 디지털 트윈, 실제 완주 검증, CNN 성능 비교, 새 복구 제어기 배포, 연속 실차 위치 정답 확보는 이번 시험의 결과가 아니다. 기본 지도와 카메라 기하는 맞는 것으로 두었고 장착 각도 오차·실제 인쇄 맵의 변형은 추가하지 않았다. 반사/이음새 시험의 비슷한 정지 이유를 실제 사건의 단일 원인 확정으로 바꾸어 해석하지 않는다.
