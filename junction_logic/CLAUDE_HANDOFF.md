## 검토 목적과 핵심 결정

외곽 차선 유지가 완료된 뒤 교차로 처리를 통합하기 위한 설계 자료다. **특정 경로 생성 방식을 정답으로 지정하지 않고, 행동 정책과 경로 생성 방법을 분리해 비교 비용을 줄이는 것**이 목적이다. 이 문서에 기존 제안과 대안 비교의 최종 판단을 통합했으므로 앞선 두 문서를 따로 읽을 필요는 없다.

사용자 규칙은 중앙 사거리 진입 시 항상 우회전이며, 삼거리는 향후 표지판 모델이 알려주는 직진·좌회전·우회전을 수행하는 것이다. 지도상 존재하지 않는 출구는 선택하지 않는다. 외곽선이 보이지 않는 동안에도 선택 출구를 유지하되, 유효한 경로를 확인하지 못하면 정지하는 구조를 제안한다.

Claude가 우선 판단할 사항은 다음과 같다.

1. 실제 주행에 사용하는 코드 버전과 단일 경계 추정의 활성 여부.
2. 교차로 접근 시 확보 가능한 출구 위치·접선·경계·차량 상대 이동 정보.
3. 같은 입력으로 비교할 경로 후보. 우선 수학적 보간과 외곽 성공 경로의 공간 템플릿을 비교하고, 단일 경계는 독립 후보 또는 보조 관측으로 평가할 수 있다.
4. 관측 공백을 견딜 조건과 출구 재획득 기준, 차체 전체의 도로 여유 검사 방법.

## 교차로 행동 정책

田 모양 도로를 9개 노드와 12개 연결 구간으로 표현한다. 가운데 노드는 사거리, 각 변의 가운데 노드는 삼거리, 모서리는 일반 코너다. 노드 좌표는 연결 관계만 뜻하며 실제 거리나 회전 반경을 뜻하지 않는다.

| 상황 | 행동 |
|---|---|
| 중앙 노드임이 확인된 사거리 | 항상 right. 표지판이 left/straight여도 시험 규칙을 우선하고 충돌을 로그에 남김 |
| 삼거리의 유효하고 확인된 표지판 명령 | 해당 진입 방향에서 가능한 행동이면 채택 |
| 표지판 모델 연결 전 시험 | 사전에 등록한 명시적 경로 명령 사용 |
| 해당 방향 출구가 지도에 없음 | 정지 후 명령 또는 위치 확인. 임의 직진으로 대체하지 않음 |
| 위치가 불확실하거나 표지판이 상충함 | 진입 전에 정지. 경계가 사라졌다는 사실만으로 중앙 사거리로 간주하지 않음 |
| 선택한 출구는 있으나 시야에서 일시적으로 사라짐 | 행동은 유지. 관측 경계 또는 검증된 경로로 추종할 수 없으면 정지 |

우선순위는 **정지 조건 → 지도상 출구 유효성 → 중앙 우회전 규칙 → 확정 표지판 → 명시적 시험 경로**다. 중앙 우회전 규칙이 장애물이나 경로 불확실성을 무시하고 진입하라는 의미는 아니다.

같은 삼거리라도 접근 방향에 따라 직진+좌회전, 직진+우회전, 좌회전+우회전 중 하나가 된다. 따라서 `junction_id`뿐 아니라 `incoming_edge`가 필요하다. 예를 들어 아래 중앙 삼거리에 왼쪽에서 진입하면 직진과 좌회전만 가능하고, 가운데 세로 도로에서 내려오면 좌회전과 우회전만 가능하다.

노드 식별이 필요한 구성에서는 시작 위치와 경로 이력, 카메라 단서를 함께 사용한다. 국소 교차로 인식만으로 행동을 결정하는 구성도 비교할 수 있다. 대칭인 도로에서 폭이나 횡단보도 하나만으로 현재 노드를 유일하게 결정할 수 있다고 가정하지 않는다. 외곽 코너 횟수만으로 정확한 위치를 확정하는 것도 피한다.

## 통과 상태와 완료 조건

| 상태 | 수행 내용 | 다음 상태로 가는 근거 |
|---|---|---|
| FOLLOW | 기존 차선 유지 | 여러 프레임의 교차로 관측이 진입 문맥과 일치하면 APPROACH. 지도를 쓸 경우 다음 교차로와도 대조 |
| APPROACH | 감속, 원본 경계 이력 유지, 진입 폭 동결, 행동 후보 선정 | 출구 존재·경로·차체 여유·위치 신뢰도·진입 위치가 확인되면 COMMITTED |
| COMMITTED | 이번 방문의 행동과 출구를 고정하고 회전/직진 경로 추종 | 차체가 출구 쪽으로 이동하고 출구 차선 후보가 나타나면 REACQUIRE |
| REACQUIRE | 기존 경로와 새 차선의 위치·방향 일치 확인, 점진적으로 차선 추종에 인계 | 실제 경계 관측과 출구 진행 방향이 연속 확인되면 FOLLOW |
| STOP | 출력 정지 요청과 원인 기록 | 자동 시간 경과로 재출발하지 않고 명시적 복구 또는 재초기화 |

COMMITTED 이후 새 표지판이나 한 프레임의 분기 누락으로 행동을 바꾸지 않는다. 카메라 프레임 정지, 위치 추정 신뢰도 저하, 통과 시간 초과 등은 행동 변경이 아니라 STOP의 이유다. 비상 정지는 어떤 상태보다 우선한다.

통과 완료는 단순히 90도 회전하거나 일정 시간이 지났다는 이유로 인정하지 않는다. 선택한 출구와의 위치·방향 일치, 경로 진행도, 실제 차선 관측의 지속성으로 결정한다. 초기 비교에서는 양쪽 경계를 이용한 보수적인 완료 기준과, 출구 방향·진행도에 단일 경계 또는 출구 노면을 결합한 기준을 구분해 시험한다. 양쪽 경계만 필수로 요구하면 가림 상황에서 불필요한 정지가 늘어날 수 있다.

완료 시 `previous_node → current_node → selected_exit`의 이력을 갱신하고 표지판 명령을 소비 처리한다. 같은 교차로를 나중에 다시 지날 수 있으므로 지도 노드 ID와 별개로 방문마다 새로운 `event_id`를 만든다. 단순한 시간 지연만으로 재감지를 막지 말고 교차로 영역을 벗어났다는 증거도 사용한다.

행동 고정은 경로 좌표를 영구히 고정한다는 뜻이 아니다. 선택 출구는 유지하면서 새 관측으로 경로를 갱신하고, 잘못된 곡선은 중단한다.

## 경로 생성 대안 비교

구현 부담은 상대 비교이며 실측 시간이나 성공률이 아니다. 각 방법의 복잡도에는 영상에서 입력을 얻는 비용까지 포함해야 한다.

| 방법 | 필요한 입력 | 장점 | 주된 부작용 | 우선 확인할 것 |
|---|---|---|---|---|
| 한 경계의 법선 오프셋 | 신뢰할 경계, 구간 폭, 도로 방향 | 기존 코드 재사용 가능, 현재 관측에 반응 | 잘못된 섬 경계 선택, 접선 잡음, 폭 오인, 좁은 코너의 오프셋 특이점 | 어느 물리 경계를 얼마나 오래 추적하는가 |
| 진입/출구 사이 Hermite 또는 Bézier 보간 | 두 끝점, 두 접선, 조절할 핸들 길이 | 입력 적음, 후보 여러 개 생성 쉬움 | 보기 좋은 곡선도 섬을 침범, 끝점이 안 보이면 추측에 의존 | 출구 끝점과 접선을 실제로 얻을 수 있는가 |
| 원호 또는 두 원호 연결 | 접선과 접점, 반경 또는 추가 제약 | 파라미터 해석 쉬움, 곡률 검증 간단 | 단일 원호로 맞지 않는 진입/출구, 연결점 곡률 불연속 | 실제 접선 교점에서 접점까지 거리가 일치하는가 |
| 외곽 성공 경로의 공간 템플릿 | 실측 경로와 상대 위치, 새 교차로의 배치 | 성공한 곡률 변화 패턴 활용 | 외곽과 내부 폭·반경 차이, 좌우 구동 비대칭 | 공간 경로가 있는가, PWM 시계열만 있는가 |
| 진입 직전 경로의 짧은 외삽 | 최근 경로와 프레임 간 이동 | 짧은 관측 공백을 쉽게 메움 | 실제 갈림 방향을 생성하지 못함, 오차 누적 | 공백 길이와 예측 오차의 관계 |
| 노면 영역에서 출구 목표로 경로 탐색 | 신뢰 가능한 노면 마스크와 차량 자세 | 경계선이 일부 끊겨도 넓은 영역 활용 | 횡단보도·빛반사 때문에 가짜 장애물, 섬까지 노면으로 오분류 | 마스크가 자유공간을 보수적으로 나타내는가 |
| 전역 지도와 위치 추정으로 경로 생성 | 측량 지도, 차량 자세와 불확실성 | 규칙·경로·위치를 일관되게 처리 | 준비 비용 큼, 대칭 위치 혼동 | 현재 과제에서 이 비용이 필요한가 |

실험 후보를 줄인다면 **보간 후보와 공간 템플릿 후보를 같은 영상·같은 출구 조건에서 비교**하는 것이 유용하다. 단일 경계는 주 경로가 아니라 후보 경로의 보조 관측으로도 쓸 수 있다. 전역 지도 구축을 먼저 완료할 필요는 없다. 출구를 전혀 관측하지 못하고 상대 이동도 모르면 보간이나 템플릿도 자동으로 이 문제를 해결하지 못한다.

## 단일 경계 추정의 조건과 부작용

경계 곡선 b(s)와 도로 안쪽 단위 법선 n(s)에 대해 `c(s)=b(s)+d·n(s)`가 기본형이다. d는 해당 경계에서 중앙까지의 거리이며 항상 현재 도로폭/2라고 단정할 수 없다. 한쪽의 섬 모서리와 반대쪽 외곽선이 동심 곡선이 아닐 수 있기 때문이다.

부호를 일관되게 정의한 평면 곡선에서 상수 오프셋의 곡률은 `κ_offset=κ/(1−dκ)`이다. `1−dκ`가 0에 가까워지면 접힘이나 큰 곡률이 생길 수 있다. 교차로의 잘못된 경계를 따라 평행 이동한 결과가 매끄러워 보인다는 이유만으로 주행 가능한 중앙선이 되지는 않는다. 폭 d가 구간에 따라 변하면 이 단순 공식 대신 실제 생성 곡선을 미분해 곡률을 확인한다.

18cm 도로에서 폭을 26cm로 잘못 사용하면 반폭 오차는 4cm다. 차량 폭 15.5cm일 때 평행 중앙 정렬 여유 1.25cm보다 크다. 이는 가능한 오차의 크기를 설명하는 계산이지 현재 코드가 실제로 그 오차를 냈다는 주장은 아니다.

실험 체크: 실제 경계와 추정 경계를 별도 색으로 표시, 선택한 경계 ID 기록, 구간별 폭 고정 여부 기록, 정답 경로와의 편차 비교. 중심선 오차가 줄어도 차량 모서리의 최소 여유가 줄면 채택 근거가 되지 않는다.

## 수학적 보간 후보

픽셀 좌표나 좌우 PWM을 직접 보간하기보다 보정한 지면 좌표의 경로를 후보로 만든다. 90도 회전을 `y=f(x)` 하나로 표현하면 수직 접선 부근에서 불편하므로 매개변수 곡선이 적합하다.

3차 Bézier는 다음과 같다.

```text
B(u) = (1−u)^3 P0 + 3(1−u)^2 u P1 + 3(1−u)u^2 P2 + u^3 P3
P1 = P0 + a·t_in
P2 = P3 − b·t_out
0 ≤ u ≤ 1,  a > 0, b > 0
```

P0/P3는 진입/출구 기준점, t_in/t_out는 단위 접선이다. 이 조건은 끝점과 접선 방향을 맞추지만 곡률 연속성이나 도로 안쪽 통과를 보장하지 않는다. 직선과 곡률까지 연속으로 연결하려면 추가 제약을 둔 고차 곡선, clothoid 등의 부담이 생긴다. 우선 저속 비교에서는 a,b를 작은 후보 집합으로 탐색하고 도로 침범·최대 곡률·곡률 변화량·현재 경로와의 변화량으로 평가하는 구성이 단순하다.

평면 곡률의 크기는 `|x'y''−y'x''|/(x'^2+y'^2)^(3/2)`로 계산한다. 분모가 작은 정지점, 루프, 역진행, 출구 반대 방향 접선을 제거한다. 경로를 매 프레임 재생성할 경우 후보가 바뀌며 조향이 튀지 않도록 이전 경로와의 연속성도 평가한다. u는 시간도 주행거리도 아니므로 같은 u 간격을 같은 속도로 실행하지 않는다.

입출구 중 출구가 안 보이면 이는 보간보다 외삽/가설 경로 생성에 가깝다. 그 경우 지도나 템플릿이라는 추가 가정과 불확실성을 명시한다. 직선 보간으로 두 차선 끝점을 단순 연결하면 회전 안쪽 섬의 모서리를 가로지를 수 있다.

## 외곽 커브 재사용 후보

### 회전각만 재사용

외곽 코너와 교차로가 모두 90도라도 경로 반경과 회전 시작점은 정해지지 않는다. 일반적으로 방향 변화는 `Δψ=∫κ(s)ds`이므로 같은 각도를 만드는 곡률 분포가 무수히 많다. 또한 바퀴 속도 차로 회전하는 이 차량에는 조향 서보의 단일 각도라는 입력이 없다. 영상의 heading, 경로 곡률, 차체의 총 회전각을 구분한다.

### 일정한 곡률이나 반경 재사용

성공한 외곽 반경 R을 초기 후보로 쓰는 것은 가능하다. 다만 90도 원호는 접선 교점에서 양쪽 접점까지 각각 R만큼 떨어지는 배치를 요구한다. 교차로에서 그 배치를 확보하지 못하면 원호의 시작점이나 반경을 바꿔야 한다. 현재 `path_R`는 관측 중앙선의 원 피팅 결과이고 `curv_pp`는 목표점을 향한 제어 곡률이므로 둘을 같은 실측 회전 반경으로 취급하지 않는다.

### 공간 경로 또는 곡률 분포 재사용

유용한 재사용 단위는 진입 좌표계의 경로 `p(s)` 또는 주행거리 기준 `κ(s)`다. 위치·방향을 새 진입에 맞추고, 필요하면 크기를 조절한다. 균일 배율 λ로 경로를 줄이면 곡률은 `κ_new(s_new)=κ_old(s_new/λ)/λ`가 된다. 더 작은 교차로에 축소한 경로가 더 큰 곡률을 요구한다는 뜻이다. 직사각형으로 비균일 축소하면 이 공식이 성립하지 않으므로 곡률을 다시 계산한다.

좌우 거울상은 기하 후보를 만들 수 있지만 모터·타이어·바닥 마찰의 좌우 차이까지 없애지 않는다. 좌우는 따로 검증한다. 가장 가까운 후보 몇 개를 초기값으로 사용하고, 출구 관측으로 맞추는 방식이 원본 경로를 고정 재생하는 것보다 수정 여지가 있다.

### PWM과 시간 시퀀스 재사용

구현은 가장 쉽지만 배터리·슬립·바닥 마찰·시작 자세에 민감하다. 이번 차량은 충전 전후 전원 동작도 달랐고 회전 시 작은 PWM에서 한쪽 바퀴가 움직이지 않은 관측도 있었다. 다만 이 사실만으로 속도 변화량을 정량화할 수는 없다. PWM 로그는 측정 궤적이 아니므로 궤적 템플릿으로 바꾸려면 영상 이동 추정이나 별도 위치 측정이 필요하다. 시간 재생은 제한된 비교 실험용 후보로 두고 양산할 경로 방식으로 미리 채택하지 않는다.

## 합성 기하를 이용한 수치 비교

아래는 **실제 트랙이 아닌 합성 기하**다. 시작 (0,0)cm, 끝 (20,20)cm, 진입 전방/출구 오른쪽 접선이 같은 Bézier 곡선에 a=b만 다르게 설정했다.

| 핸들 길이 a=b | 방향 변화 | 샘플 기준 최소 반경 |
|---|---|---|
| 8cm | 90도 | 8.00cm |
| 약 11.046cm | 90도 | 약 19.84cm |
| 16cm | 90도 | 약 9.55cm |

같은 끝점·같은 회전각이라도 구동 난도와 차체가 차지하는 영역은 달라진다. 핸들이 길수록 항상 완만해지는 것도 아니다. [계산 코드](</C:/workspace/AutoMobile/junction_logic/compare_geometry.py>)와 [수치](</C:/workspace/AutoMobile/junction_logic/geometry_comparison.json>)를 제공한다. 촘촘한 샘플 비교이며 연속 구간의 엄밀한 최적화 증명은 아니다.

또한 차체 기하 중심이 반경 20cm 원을 돌고 차체 방향이 접선과 일치한다고 가정하면, 26×15.5cm 직사각형의 바깥 모서리 반경은 `sqrt((20+7.75)^2+13^2)≈30.64cm`다. 중심선에 반폭만 더한 27.75cm보다 약 2.89cm 더 바깥까지 쓴다. 이 가정은 실제 구동축 기준점과 다를 수 있으므로 차체 오프셋을 측정해야 하지만, 중심선만 검사하는 것이 부족하다는 예시로 사용할 수 있다.

## 관측 공백과 좌표계 관리

접근 도로폭, 출구 도로폭, 교차로 내부 형상을 구분한다. 교차로가 넓어진 관측 폭으로 도로폭을 곧바로 갱신하지 않는다. 18cm에서 21cm로 바뀌는 구간 전체에 같은 폭을 고정하는 것도 피한다.

진입 직전에 관측한 진입 접선과 선택 출구의 접선을 잇는 경로를 유지한다. 후보로 접선이 연속인 원호 또는 3차 곡선을 사용할 수 있다. 저장하는 것은 straight/left/right라는 행동과 경로 생성 방식이며, 모든 교차로에 동일한 PWM이나 회전 시간을 재생하는 방식이 아니다. 좌우 회전도 도로폭과 진입 방향에 따라 다른 경로가 필요하다.

저장 경로는 진입 시점의 고정 좌표계에 두고, 이후 프레임마다 추정한 차량 이동으로 현재 차량 좌표계에 변환한다. 예전 이미지의 좌표를 그대로 현재 좌표처럼 사용하면 차량이 움직인 만큼 목표점이 잘못된다. 좌우 경계 추적과 출구 재관측으로 위치 추정을 계속 보정한다.

현재 확인한 주행 코드에는 엔코더/IMU를 이용한 이동 추정이 없다. 카메라 기반 지면 특징점 이동 또는 교차로 경계의 지도 정합을 추가하는 방안을 우선 검토한다. 이를 실제 영상으로 검증하기 전에는 양쪽 경계가 모두 없는 구간을 자율 통과할 준비가 되었다고 판단하지 않는다. PWM은 속도 측정이 아니므로 PWM×시간만으로 위치를 확정하지 않는다. 특징점 부족·반사·그림자·흔들림 때는 추정 오차를 늘리고, 허용 범위를 넘으면 정지한다.

경로의 목표점에서 기존 pure pursuit와 wheel_speeds를 사용할 수 있다. 곡률 단위는 기존 코드와 같은 1/cm, 부호는 오른쪽 양수로 유지한다. 반면 지도 좌표계와 영상 좌표계는 별개이므로 변환 규약을 명시해야 한다.

## 차체 크기와 경로 여유

사용자 실측은 차체 전체 길이 26cm, 바퀴 포함 폭 15.5cm, 내부 세로 도로폭 18cm, 내부 가로 21cm다. 외곽 왼쪽의 측정 폭은 26cm, 아래는 24cm이며 다른 지점의 최소 폭은 아직 확정되지 않았다.

18cm 도로에 평행하게 중앙 정렬하면 좌우 여유는 각각 1.25cm다. 26×15.5cm 직사각형으로 보수적으로 근사하면, 도로 방향과 θ만큼 틀어진 차체의 횡방향 점유폭은 `15.5 cos θ + 26 sin |θ|`다. 5도에서는 약 17.71cm로 양쪽 여유가 각각 약 1.46mm밖에 남지 않는다. 이는 평행한 직선 도로에서의 정적 기하 계산이며 실제 허용 조향각이나 제어 목표값은 아니다.

따라서 경로 중심점만 도로 안에 있는지 검사해서는 부족하다. 차체 네 모서리가 회전하며 지나가는 영역 전체와 추정 오차, 정지거리를 포함해 검사해야 한다. 카메라 원점과 차체 기준점의 오프셋도 필요하다. 기존 코드의 WHEEL_TRACK_CM=13.0은 추정된 바퀴 중심 간격이고 차폭 15.5cm나 전체 길이 26cm와 서로 다른 값이다.

회전 반경은 사진에 표시된 32cm·37cm 같은 길이를 곧바로 사용하지 않는다. 그 표기가 반경이라는 근거가 없다. 삼거리별 진입/출구 접선 위치, 경계 곡률, 차량의 실제 회전 반경을 측정해 경로를 정한다. 이전 track_guard의 가상 데모 지도도 실측 지도 대신 사용할 수 없다.

## 제어기와 관측기의 공통 검토

어떤 경로를 선택해도 같은 pure pursuit를 쓰면 경로 생성 차이만 비교하기 쉽다. 그러나 긴 lookahead는 급한 곡선에서 추종 편차를 만들 수 있으므로 현재 LOOKAHEAD_CM=20을 모든 교차로에서 최적이라고 가정하지 않는다. 경로를 생성하는 문제와 그 경로를 추종하는 문제를 분리한다. [Coulter의 원 보고서](https://www.ri.cmu.edu/pub_files/pub3/coulter_r_craig_1992_1/coulter_r_craig_1992_1.pdf)는 목표점의 차량 좌표 변환과 lookahead에 따른 추종 특성을 설명한다. 이를 본 차량의 특정 파라미터가 적절하다는 근거로 확대하지 않는다.

현 카메라 지면 좌표 원점과 실제 차체의 운동 기준점이 다르면 같은 pure pursuit 수식에 목표점을 넣어도 제어 오차가 생길 수 있다. 양자 사이 평행 이동·회전을 먼저 확인한다. 문헌의 특정 차종 축 배치를 이 차체에 그대로 적용하지 않는다.

노면 마스크 방식은 현 `edge_masks`의 어두운 픽셀 마스크를 그대로 자유공간으로 쓰면 안 된다. 흰 횡단보도가 빠지고 조명에 따라 노면이 달라질 수 있다. 작은 구멍을 메우는 처리도 큰 섬을 메워 가짜 통로를 만들지 않는지 확인한다. 차량 중심의 2D 점 경로만 찾는 격자 탐색보다 자세와 차체 영역까지 확인하는 후속 검사가 필요하다.

## 표지판과 주행 루프의 인터페이스

표지판 모델은 모터를 제어하지 않고 `SignCommand`만 전달한다.

```python
SignCommand = {
    'event_id': '이번 교차로 방문 식별자',
    'action': 'straight | left | right',
    'captured_at': '단조 증가 시계 기준 촬영 시각',
    'confidence': '검증된 모델의 신뢰도',
    'track_id': '같은 표지판의 영상 추적 ID',
    'confirmed': '여러 서로 다른 프레임에서 일관되게 확인되었는지',
}
```

`event_id`는 표지판 모델이 임의 생성하지 않고 경로 관리자에서 발급한 교차로 문맥에 연계한다. 같은 프레임의 반복 처리로 확인 횟수를 늘리지 않는다. 예측 확률이 높다는 이유만으로 단일 프레임을 확정하지 않는다. 유효 시간과 신뢰도 임계값은 모델 검증 후 조정한다.

아직 표지판이 먼 곳에 있을 때 확인한 명령은 해당 교차로에 연결해 저장할 수 있다. 이후 매 프레임 신호가 새로 와야만 유지하는 방식은 피하되, 다른 교차로의 오래된 명령이 재사용되지 않도록 방문 ID와 통과 완료 처리를 묶는다. 확정 전의 후보 유효 시간과 확정 후의 행동 유지 시간을 구분한다.

관측기는 `raw_det`, `observed_sides`, `branch_candidates`, `captured_at`, `confidence`, `width_measurement`를 전달한다. `raw_det`는 분기 절단 전 결과이고, `observed_sides`는 합성된 lines의 키가 아니다. confidence는 현 코드에 없으므로 새로 정의하고 검증해야 한다. 차선 미검출을 곧바로 교차로 검출로 바꾸지 않는다.

교차로 관리자는 `state`, `event_id`, `selected_action`, `exit_edge`, `path_source`, `curvature_per_cm`, `speed_limit`, `stop_reason`을 반환한다. FOLLOW에서는 기존 res.curv_pp를 사용하고, COMMITTED에서는 유효한 교차로 경로의 곡률을 사용한다. STOP은 출력 완만화 때문에 오래 끌리지 않도록 기존 비상 정지 방식과 우선순위를 합의해야 한다. 구동·전압 감시·카메라 소유권은 계속 기존 주행 루프 한 곳에서 관리한다.

## 후보 비교 실험과 공통 경로 인터페이스

1. **실제 실행 버전과 활성 분기 확인.** 실행 파일 경로, 소스 해시, 모드, observed_sides, 경계 선택 사유를 로그에 추가할지 결정한다. 현재 사용하지 않는 기능을 재사용하는 것으로 가정하지 않는다.
2. **한 번의 영상 수집을 모든 후보에 공유.** 성공한 외곽 좌/우 커브, 삼거리 접근·진입·출구, 중앙 사거리의 연속 영상에서 프레임 시각과 보정을 보존한다. 먼저 모터 없는 재생으로 후보 경로를 겹쳐 비교한다. 한 장의 사진만으로 통과 중 상태 안정성을 평가하지 않는다.
3. **끝점과 접선을 수동 지정한 오프라인 비교.** 초기에는 자동 검출까지 동시에 개발하지 않아도 된다. 동일한 수동 기준점으로 단일 경계 오프셋, Bézier 후보, 정렬한 외곽 템플릿을 비교한다. 이때 기준점은 사람이 준 것이라고 표시한다.
4. **기하 실패 후보를 먼저 제거.** 섬 침범, 출구 접선 불일치, 과도한 곡률, 차량 모서리 여유 부족 후보를 제외한다. “겉으로 매끄럽다”를 채택 기준으로 쓰지 않는다.
5. **관측 오차에 민감한지 확인.** 경계/출구 위치 ±1·2cm, 방향 ±3·5도, 한 경계 삭제 등의 합성 교란을 같은 방식으로 주입한다. 이 범위는 실제 오차 분포가 아니라 비교용 스트레스 조건이다.
6. **남은 후보만 실차 비교.** 같은 시작 자세·출력 제한·보정·바닥에서 차례로 평가하고 반대 방향도 별도 확인한다. 성공률 외에 최소 차체 여유와 복구/정지 빈도를 기록한다. 충전량은 비교 조건으로 기록하되 잔량을 추정 전압 하나로 단정하지 않는다.

실차 모터 출력·안전 감시·카메라 소유권은 기존 루프 하나에 둔다. 여기서 공급하는 후보 경로는 공통 인터페이스로 받아 비교하는 것이 통합 비용을 줄인다.

```text
CandidatePath:
  source                 # single_edge / bezier / outer_template / ...
  points_cm              # 지정된 frame_id에서의 매개변수 경로
  frame_id, captured_at  # 과거 경로를 현재 경로처럼 쓰지 않기 위한 정보
  entry_pose, exit_pose  # 추정값과 관측/가정 여부
  evidence_ids           # 경계·출구·템플릿 출처
  pose_uncertainty       # 검증 방법과 함께 정의
  validity_reason       # 유효/정지 판단 사유
```

첫 결정은 알고리즘 이름이 아니라 **현재 얻을 수 있는 입력**이다. 출구 접선이 보이면 보간 비교부터, 안정적인 성공 궤적이 있으면 템플릿 비교부터, 하나의 올바른 경계만 보이면 오프셋을 보조 관측으로 비교한다. 입력이 없는 구간은 어느 방법에서도 추가 관측이나 추정이 필요하다. 이 자료의 계산과 정책 테스트는 후보 검토용이며 실차에서 검증된 교차로 통과 알고리즘은 아니다.

## 통합 단계와 평가 기준

| 단계 | Claude가 통합할 범위 | 통과 조건 |
|---|---|---|
| 1 관측 로그 | 기존 주행 출력은 유지하고 원본 경계·분기 후보·후보 상태를 기록 | 외곽 코너, 삼거리, 사거리, 단순 라인 소실을 구분할 데이터 확보 |
| 2 행동 정책 | 지도 진입 방향별 허용 행동, 중앙 우회전, 표지판 명령 선택과 고정 | 불가능한 출구와 명령 충돌에서 정지. 중앙의 4개 진입 방향 모두 right |
| 3 삼거리 경로 후보 | 비교에서 남은 경로 생성 방식, 폭 갱신 제한, 출구 재획득 | 직진·좌·우 각 허용 접근을 저속으로 확인. 프레임별 방향 변경 없음 |
| 4 경계 공백 통과 | 차량 이동 추정과 저장 경로의 좌표 변환, 차체 통과 영역 검사 | 인위적 가림과 위치 오차에서 한계를 감지해 정지. 검증 범위 내에서 출구에 정렬 |
| 5 사거리 강제 우회전 | 중앙 위치 확인, 오른쪽 출구 경로, 규칙 우선 처리 | 4개 진입 방향과 상충 표지판에서 규칙 유지. 길이 안 보이면 직진 대체 없이 정지 |
| 6 표지판 통합 | 시각·방문 ID·여러 프레임 확인·소비 처리 | 오래된 명령, 깜빡임, 중복 인식, 재방문에서 오작동 없음 |

먼저 녹화 영상으로 무구동 재생하고, 이후 상태만 기록하는 동시 관찰 모드, 마지막으로 실제 출력을 적용하는 순서가 적절하다. 제안 시험량은 각 합법 행동과 진입 방향별 최소 10회 반복이며, 이는 초기 비교용 기준이지 무이탈 보장의 통계적 증명은 아니다.

측정값은 의도와 실제 출구 일치 여부, 도로 경계와 차체의 최소 여유, 출구에서의 횡오차·방향오차, 잘못된 교차로 검출, 정지 빈도, 행동이 바뀐 횟수, 연속 관측 공백 시간이다. 18cm 출구는 폭과 길이에 따른 여유가 작으므로 다른 폭의 출구와 분리해 평가한다. 현재 자료로 성공률이나 안전한 통과 속도를 제시할 수 없다.

임계값은 확인 시간, 최대 관측 공백, 진입 거리, 재획득 지속 시간, 최대 위치 오차를 따로 둔다. 프레임 수만으로 시간을 표현하면 처리 FPS 변화의 영향을 받으므로 타임스탬프와 함께 판정한다. 정지 가능한 접근 속도는 실측 감속도·처리 지연·교차로까지 남은 거리로 정하고, PWM 백분율을 cm/s로 취급하지 않는다.
