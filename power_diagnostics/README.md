# 모터 부하 / Pi 전원 진단

기존 `/home/pi/TEST` 및 주행 코드를 수정하지 않는 별도 도구입니다.
파이: `/home/pi/power_diagnostics/probe.py`, 노트북: 이 폴더의 `collect.py`.
확인한 배선은 기존 `lane_drive.py`와 동일합니다: 왼쪽 PWM18/IN22,27, 오른쪽 PWM23/IN25,24, 전진 IN1=0/IN2=1. 실제 좌우는 바퀴를 들고 확인하세요.
기본 PWM 1000Hz. 주파수 변경이 반드시 전압 강하를 줄인다는 전제는 없습니다.

## 실행 위치

노트북 PowerShell에서 이 폴더로 이동해서 실행합니다. Python 표준 라이브러리와 Windows OpenSSH만 필요합니다.
파이는 기존 `/home/pi/AI_CAR/env_hw/bin/python`과 gpiozero를 사용합니다.
SSH 키 인증과 기존 호스트 키 확인을 사용하며, 암호를 코드에 넣지 않았습니다.

```powershell
cd "C:\workspace\AutoMobile\power_diagnostics"
python collect.py --case idle --auto
```

위 명령은 모터 GPIO를 열지 않습니다. 입력 전압, 온도, 스로틀 상태, boot ID/PMIC 리셋값을 읽습니다.
카메라는 이 도구가 켜지 않습니다. 최초 실험은 카메라/주행 프로그램을 종료한 동일 조건에서 비교하세요.
주행/블루투스 모터 프로그램과 동시 실행하지 마세요. 기존 프로세스를 자동으로 종료하거나 자동 시작 설정을 변경하지 않습니다.
파일 잠금은 이 진단 도구끼리의 중복만 막으며, GPIO 라이브러리 외부에서 핀을 조작하는 다른 프로그램까지 차단하지 못합니다.

## 실험 순서: 한 번에 한 조건

바퀴를 들어 단단히 지지하고 바퀴가 물체/손에 닿지 않게 한 상태에서:

```powershell
python collect.py --hardware --placement lifted --case left --duty 0.20 --note "camera_off"
python collect.py --hardware --placement lifted --case right --duty 0.20 --note "camera_off"
python collect.py --hardware --placement lifted --case both --duty 0.20 --note "camera_off"
```

각 명령은 시작 전에 `START lifted`를 직접 입력해야 합니다. 3초 정지 기준 측정 → 1초 상승 → 0.5초 유지 → 1초 하강 → 2초 정지 관측으로 끝납니다.
다음 실험으로 자동 진행하지 않습니다. 각 시험 사이 바퀴의 회전 여부, 어느 쪽인지, 이상음/진동, LED, 접속 끊김, 버튼을 눌러야 복구되는지 기록하세요.
PWM 20%가 반드시 회전 가능한 값은 아닙니다. 바퀴가 돌지 않고 버티거나 소리만 나면 바로 정지하고 기계적 걸림을 먼저 확인하세요. 바퀴를 손으로 잡아 의도적으로 구속하지 마세요.
첫 단계가 정상일 때만 같은 조건에서 0.25/0.30 등 한 단계씩 비교합니다. 허용 상한은 0.50이며 최대 출력 시험이 목표가 아닙니다.

들어 올린 시험이 정상일 때 바닥의 넓고 평평한 빈 공간에서:

```powershell
python collect.py --hardware --placement floor --case both --duty 0.20 --ramp 0.5 --hold 0.2
```

`START floor`를 입력해야 시작합니다. 실제 이동 거리는 바닥/배터리/모터에 따라 달라지므로 좁은 트랙에서는 하지 마세요.
필요하면 `--case left`/`right`로 바닥 한쪽 시험도 가능하지만 차량이 회전하므로 주변 공간을 확보해야 합니다.
`placement`는 실험 기록/시작 확인용이며 센서로 들림을 검증하지 않습니다.
카메라 부하 비교는 먼저 모터 없이 카메라만 별도로 실행하여 `idle`을 기록한 다음 같은 모터 조건과 비교합니다. 카메라 프로그램이 모터 GPIO까지 잡는 주행 프로그램이면 동시에 실행하면 안 됩니다.

## 정지 조건

* Ctrl+C, 보드 SW1~4 버튼(기존 pull-down 배선 기준).
* 노트북 heartbeat가 약 1초 이상 없거나 SSH 입력이 닫히면 정지. 노트북은 0.2초 간격 송신.
* 입력 전압 4.80V 미만, 현재 저전압 비트, 온도 80°C 이상, 센서 읽기 실패/전압 샘플 0.75초 초과 시 정지.
* stdout 큐 포화, 예외, 실험 종료 시 PWM=0 및 GPIO 해제.
* 모터는 START 전에는 GPIO를 열지 않으며, 기본 실행은 관측 전용입니다. 재연결/재부팅 후 자동 모터 재가동은 없습니다.

이것은 Linux/Python이 실행될 때의 정지 시도입니다. OS 멈춤·SIGKILL·전원 차단·핀/드라이버 상태 이상에 대한 하드웨어 정지는 보장하지 않습니다.
통신 끊김 정지의 1초도 바닥에서는 이동하기에 긴 시간입니다. 정지 버튼과 전원 차단 수단을 가까이 두세요.
임계값은 보수적인 실험 중단 기준이지 배터리 진단의 확정 기준이 아닙니다. 강하를 관측하려고 보호를 해제하지 않습니다.

## 노트북에 남는 자료

`runs/<시각>/config.json`: 시험 종류/조건/메모.
`telemetry.jsonl`: 파이 단조 시각과 노트북 수신 시각, 전압, 온도, 스로틀 비트, 당시 명령 PWM, 단계.
`summary.json`: 단계별 최소/평균 전압, 실제 샘플 간격, 마지막 수신 기록, 종료 이유.
`ssh_stderr.txt`: SSH/파이 오류.

파이 SD카드에 고빈도 로그를 쓰지 않고 노트북에 flush 및 약 0.5초마다 fsync합니다. 이미 수신된 기록만 보존할 수 있으며 전원 차단 직전의 전송 중 데이터는 소실될 수 있습니다.
기본 측정 목표는 약 10Hz이나 vcgencmd 비용과 부하로 느려질 수 있습니다. `max_observed_sample_gap_s`를 확인하세요.
샘플은 전압·온도·플래그를 순서대로 읽으므로 동시 측정이 아닙니다. 실제 측정 시작/완료 동안 PWM이 조금 변할 수 있습니다.

Pi 입력 `EXT5V_V`는 배터리 원단 전압이 아니며, 모터 전류를 측정하지 않습니다. 밀리초 급 과도 현상은 ADC polling/SSH가 놓칠 수 있습니다.
마지막 전압이 5V여도 다음 순간 전압 강하를 배제할 수 없습니다. 확증하려면 입력 레일의 빠른 전압 측정과 모터 전류 측정이 필요하지만, 이 도구는 추가 하드웨어 없이 비교 근거를 수집합니다.

## 결과 해석

| 관측 | 다음으로 의심/확인할 것 |
|---|---|
| 들린 상태 한쪽에서만 실패 | 해당 모터·기어/바퀴 걸림·배선·드라이버 채널. 전류를 측정한 확정 진단은 아님 |
| 각 모터는 정상, 양쪽에서 실패 | 합산 기동 전류와 전원 경로/배터리 공급 여유 |
| 들렸을 때 정상, 바닥에서 실패 | 접지 부하·마찰·기어/차체 문제와 부하에 따른 전원 강하 |
| 카메라 추가 시 악화 | 시스템 총부하와 처리/열 영향 |
| SSH만 끊기고 boot ID 유지 | Wi-Fi/프로세스 장애 가능성. 전원 꺼짐으로 단정 금지 |
| 버튼 후 boot ID 변경 | 재부팅 확인. 원인은 전압·PMIC 리셋값·현장 관측과 함께 판단 |

꺼지면 버튼으로 복구한 뒤 `python collect.py --case idle --auto --note "after_failure"`로 새 boot ID/PMIC 값을 남기세요.
PMIC 값 0은 과거 장애가 없었다는 증명이 아닙니다. 전압, 배터리 보호회로, 접촉 불량, 모터 노이즈 등 가능한 원인을 구분해야 합니다.

## 충전 후 카메라 포함 방향별 시험 (2026-10-30)

```powershell
python collect.py --hardware --vision --placement floor --case sequence --duty 0.30 --ramp 1 --hold 3
```

`START floor` 입력 후 촬영/영상처리 준비, 3초 기준 측정, 직진 → 좌회전 → 우회전 → 후진.
각 동작은 가속 1초 + 유지 3초 + 감속 1초이며 동작 뒤 2초 정지한다.
좌회전 L/R=0.105/0.30, 우회전=0.30/0.105, 후진=-0.30/-0.30.
각도/이동거리를 제어하지 않으며 원위치 복귀도 보장하지 않는다. 비워진 공간에서 감독하에 시험한다.
`--hold`는 sequence에서 최대 5초. 기본 hold는 여전히 0.5초이므로 위 명령에 명시해야 한다.
SW 버튼, Ctrl+C, 통신 끊김, 전압/온도 이상으로 중단. 프로그램은 자동 재시도하지 않는다.
`--vision`은 /home/pi/TEST의 기존 보정과 lane_pipeline.analyze를 사용하되 검출 결과로 모터를 제어하지 않는다.
맨바닥에서도 시험 가능. 영상 프레임 저장/기존 주행 CSV 쓰기 부하는 재현하지 않으므로 기존 주행과 완전히 동일한 부하는 아니다.
카메라 처리가 2초 이상 멈추면 구동 중단. 시뮬레이션은 실제 카메라/GPIO를 사용하지 않는다.
방향별 전압은 각 실행 폴더 summary.json에 따로 기록한다.


## 클로드 제어값으로 연속 조향 비교

```powershell
python collect.py --hardware --placement floor --case claude --duty 0.30 --hold 3
```

START floor 입력. 카메라/영상처리는 자동 활성화. 총 구동 약 12초:
직진 3초 → 좌회전 3초 → 우회전 3초 → 직진 3초. 중간 정지 없음.
실제 /home/pi/TEST/lane_drive.py를 읽기 전용으로 import하여 wheel_speeds, slew,
STEER_SMOOTH, ACCEL_PER_S, PWM_FREQ_HZ를 사용한다. 파일 해시와 상수는 controller_config에 기록.
--ramp는 이 모드에 적용하지 않는다. --frequency 대신 원본 PWM 상수를 쓴다.
곡률 입력만 0, -0.05, +0.05, 0 (1/cm)로 정한 시험이며, 실제 바닥의 경로를 추종하지 않는다.
현재 원본 상수에서 직진 L/R=0.30/0.30, 좌=0.135/0.265, 우=0.265/0.135로 수렴.
0.05는 차량 중심 경로의 명목상 반경 20cm에 해당하지만 실측 반경/각도는 보장하지 않는다.
기존 실험보다 빠른 가속과 정지 없는 조향을 비교한다. 급격한 무제한 출력 변화 시험은 아니다.
제어 호출 간격은 약 15Hz이며 실제 주행의 프레임별 지연까지 그대로 재현하지 않는다.
추가 안전 감독(4.80V 정지, 통신/영상처리 멈춤 정지)은 유지한다.
SD 사진/CSV 저장 부하는 추가하지 않았다. 원본 파일과 주행 보정값은 수정하지 않는다.
후진은 원래 lane_drive 기본 운행 순서가 아니므로 이 모드에는 포함하지 않는다.
