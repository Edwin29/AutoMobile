# 실차 시험 절차 — hyb2m (2026-11-11 저녁)

이 시험에는 Pi의 `~/hybrid_mission` 폴더를 쓴다. 2026-11-11 오후에 배포했고, 아래 항목은 사전 점검까지 마쳤다(카메라·모터는 쓰지 않음).
- 처리 시간: 저장된 실차 사진 300장 기준으로 조향 루프 중앙값 7ms, 최대 10ms. 지도는 별도 프로세스에서 중앙값 58ms.
- Pi 위 가짜 장비 모드: 사거리 남쪽 진입 → 제자리 우회전 통과.
- 실제 카메라와 모터로는 아직 한 번도 돌리지 않았다. **E0부터 순서대로 진행한다.**

## 공통

```bash
ssh pi@<Pi 주소>
cd ~/hybrid_mission
./run_mission.sh --help          # 옵션 목록
```

- **정지 방법:** Ctrl+C, 보드 버튼, 두 번째 터미널에서 `./send.sh quit` 중 하나. 루프가 0.5초 멈추면 감시 장치가 모터를 0으로 만든다.
- **모터:** `--drive`가 없으면 모터를 쓰지 않는다(드라이런: 카메라와 판단만).
- **명령 보내기:** 두 번째 SSH 터미널에서 `./send.sh right | left | straight | stop | resume | resume_all | stop3 | quit`를 쓴다. `./send.sh -i`는 키 입력 모드, `./send.sh --listen`은 교차로 판단 이벤트를 화면에 보여 준다.
  - **정지는 사유별로 관리한다.** 예를 들어 `./send.sh stop --reason stop_sign` 다음에 `./send.sh stop --reason red_light`를 보냈다면, `resume --reason stop_sign`만으로는 출발하지 않는다. 남은 정지 사유가 모두 풀려야 출발한다. 사유를 안 쓰면 `orchestrator` 하나로 취급한다.
  - `stop3`은 수동 시험용 도구다. 명령을 **보낸 뒤** 3초가 지나면 재개를 보낸다. 차가 실제로 멈춘 시점부터 3초를 세는 것은 오케스트레이터가 할 일이다.
  - JSON 명령에 `command_id`를 붙이면, 같은 id가 다시 와도 한 번만 처리한다.
- **기록:** `~/hybrid_mission/pi_runs/<모드>_hyb2m_<시각>/` 아래에 `steps.jsonl`(매 프레임), 사진(기본 3프레임마다), `summary.json`(교차로 판단 기록과 정지·재개 기록)이 남는다. 시험이 끝나면 폴더째 가져온다.
  - 사진은 별도 스레드가 저장한다. 밀리면 버리고 개수를 `summary.json`의 `frames_dropped`에 남긴다.
- **지도 입력:** 지도의 운동 추정에는 **실제로 모터에 쓴 값**만 들어간다. 드라이런은 0, 정지 명령과 감시 장치 정지도 0이다. 수정 전에는 드라이런 3초 동안 지도 위치가 20.7cm 표류했고, 수정 뒤에는 0.0cm다(시뮬레이터 확인).
- **휴대폰 촬영:** 가능하면 위에서 내려다보며 촬영한다. 선 밟음, 정지 거리, 회전 중 밀림을 영상으로 판정한다.
- **차 위치 기준점:** 차량 앞끝에서 14.5cm 뒤의 차체 중심선이다(시뮬레이터와 같다). 처음 놓는 위치의 오차는 ±2cm, ±3° 정도면 된다.

## 미리 만든 시나리오로 자동 명령 (`--script`)

차가 달리는 동안 손으로 명령을 넣기 어려울 때 쓴다. 오케스트레이터 대역이 **차 자신의 지도 위치**를 보고 정해진 곳에서 방향 예약, 정지, 재개를 자동으로 넣는다(실제 위치 정답은 쓰지 않는다).

```bash
./run_mission.sh --list-scripts                                   # 준비된 시나리오와 분홍 점선 번호
./run_mission.sh --drive --direction cw  --script inner_loop      # 남쪽 우회전 → 사거리 빨간불 4초 → 동쪽 합류
./run_mission.sh --drive --direction ccw --script inner_loop      # 남쪽 좌회전 → 사거리 빨간불 4초 → 동쪽 합류
./run_mission.sh --drive --direction cw  --script all             # stop 표지판 3초 + 위 내용
./run_mission.sh --drive --direction cw  --script reverse         # 합류 때 반대로 빠져 반시계로 바뀜
./run_mission.sh --drive --direction ccw --script "dir:south:W:left, red:S:4, stop:1:3"   # 직접 작성
```

| 토큰 | 의미 |
|---|---|
| `dir:교차로:갈래:방향[:거리]` | 그 갈래에서 교차로를 향해 오다가 중심까지 거리(기본 60cm) 안에 들어오면 방향을 예약한다(표지판을 본 셈) |
| `red:갈래[:정지초[:거리]]` | 사거리의 그 갈래 횡단보도 앞 거리(기본 4cm)에서 정지(사유 red_light), 정지초(기본 4초) 뒤 재개 |
| `stop:점선번호[:정지초[:거리]]` | 분홍 점선이 차 앞끝 거리(기본 20cm) 앞에 오면 정지(사유 stop_sign), 정지초(기본 3초) 뒤 재개 |

- 각 토큰은 한 번만 발동한다. 지도가 위치를 잃었으면(sxy > 2) 발동하지 않는다. 방향은 그 경우 기본값으로 가며, 표지판을 놓친 것과 같다.
- 발동 기록은 `summary.json`의 `script`(발동 / 미발동)에 남는다. `./send.sh`로 넣는 수동 명령과 같이 써도 된다.
- 시뮬레이터 확인(2026-11-11): 시계·반시계 안쪽 순환, 전체 시나리오, 반대 합류 모두 의도대로 동작했다.

## 주행 방향 (시계 / 반시계)

- `--direction`은 **출발할 때** 방향이다. 출발 구역에서 차가 남쪽을 보면 `cw`, 북쪽을 보면 `ccw`. 틀리면 지도가 위치를 계속 놓친다(16:38 실행: 정합 29%, 방향을 맞춘 16:42 실행: 88%).
- 합류 때 반대로 빠지면 주행 방향이 바뀐다. 이때 지도의 외곽 기준 경로와 다음 합류 기본값이 **실제로 나간 방향을 따라 자동으로 바뀐다**. `summary.json`의 `direction_changes`에 기록된다.
- 코너 회전은 CNN이 화면을 보고 하므로 방향과 관계없다.
- `--start`는 **차를 실제로 그 자리에 놓았을 때만** 쓴다. 안쪽 도로에서 출발하면 그 도로를 지도 기준 경로로 잡는다.

## 시작 위치 옵션

| 옵션 | 의미 |
|---|---|
| (없음) | 오른쪽 빨간 선 두 줄 사이의 출발 구역. cw이면 아래(남쪽)를 보고 놓는다 |
| `--start center:S:60` | 가운데 사거리 중심에서 남쪽으로 60cm, 사거리를 바라봄(북쪽 방향) |
| `--start south:E:70` | 남쪽 삼거리에서 동쪽으로 70cm, 삼거리를 바라봄(서쪽 방향) |
| `--pose x y 각도` | 직접 지정. 각도 0 = 북쪽(+y), 시계 방향이 +. 단위 cm·도 |

삼거리 이름은 north / east / south / west이고, 갈래는 N / E / S / W다. 좌표계는 bench 지도와 같다(가운데 사거리 = (0, 0), 출발 구역은 동쪽 도로 y −63~−33).

## 순서

### E0. 드라이런 (모터 없음, 약 2분)
```bash
./run_mission.sh --max-seconds 30
```
- 차는 출발 구역에 둔다.
- 화면 로그에서 다음을 본다.
  - `sxy`가 커지지 않고 1~1.3 근처에 머무는지 (지도가 위치를 잡음. 차가 서 있으면 더 작아지지는 않는다)
  - `mode`가 `cnn`인지
  - `pwm` 두 값이 비슷한지 (직선이므로)
  - `ms`가 대략 10 이하인지
- 끝나면 사진 몇 장이 똑바로 선 화면(위가 앞)인지 확인한다.

### E1. 외곽 한 바퀴 (명령 없음 → 삼거리 4곳 모두 직진)
```bash
./run_mission.sh --drive --direction cw
```
- 출발 구역에서 시작해 한 바퀴 돌고 출발 구역을 지나면 Ctrl+C.
- 볼 것: 삼거리 4곳에서 직진하는지(`./send.sh --listen` 또는 로그의 `last`), 코너와 선 밟음.
- 되면 `--direction ccw`로 한 번 더 한다(차를 반대 방향으로 놓는다).

### E2. 사거리 제자리 우회전 (회전 보정)
```bash
./run_mission.sh --drive --start center:S:60 --stop-after-junctions 1
```
- 차를 사거리 남쪽 60cm에 북쪽을 보게 놓는다.
- 예상 동작: CNN으로 직진 → 사거리 중심 부근에서 정지(0.3초) → 오른쪽으로 제자리 회전 → 정지 → 동쪽으로 출발 → 사거리를 벗어나면 끝.
- 잴 것:
  - 정지 위치가 사거리 중심에서 얼마나 떨어졌는지
  - 회전 뒤 방향(90° 대비)
  - 회전 중 차체가 옆으로 밀린 거리
  - 선 밟음
- 조정:
  - 회전을 시작하지 못하고 떨면 `--pivot-duty 0.45`
  - 너무 빠르게 돌다 지나치면 `--pivot-duty 0.35` (기본 0.40)
- 네 방향(`center:N:60`, `center:E:60`, `center:W:60`)도 한 번씩 해 본다.

### E3. 정지·재개 인터럽트 (정지 거리)
```bash
./run_mission.sh --drive               # 1번 터미널
./send.sh stop3                        # 2번 터미널: 직선 구간에서 실행
```
- 예상 동작: 바로 정지 → 3초 → 재출발.
- 잴 것: 명령을 보낸 순간부터 멈출 때까지 더 나간 거리. 시뮬레이터에서는 약 2.3~2.5cm였다. 비전 팀이 트리거 영역을 정할 때 쓰는 값이다.

### E4. 외곽 → 안쪽 진입 + 사거리 + 합류
```bash
./run_mission.sh --drive --start south:E:70     # 1번 터미널
./send.sh right                                 # 2번 터미널: 출발 직후 (남쪽 삼거리 도착 전에)
```
- 예상 동작: 남쪽 삼거리에서 우회전(명령) → 안쪽 도로 북쪽 방향 → 사거리 우회전(규칙) → 동쪽 삼거리 도착 → 기본값(cw이면 우회전)으로 외곽 합류 → 외곽 주행.
- 사거리 횡단보도 앞에서 `./send.sh stop` → 몇 초 뒤 `./send.sh resume`을 넣으면 빨간불 시험이 된다.
- 남쪽 삼거리는 도로 폭이 24cm로 가장 좁다. 진입 회전에서 선을 밟는지 특히 본다.

### E4-b. 좁은 합류: 나눠 돌기 (안쪽 도로 → 남쪽 외곽)
```bash
./run_mission.sh --drive --start south:N:60 --stop-after-junctions 1
```
- 차를 남쪽 삼거리 북쪽 60cm(안쪽 세로 도로)에 남쪽을 보게 놓는다.
- 예상 동작: CNN으로 내려옴 → 삼거리 입구에서 정지 → 오른쪽으로 약 60° 회전 → 약 10cm 전진 → 나머지 약 30° 회전 → 서쪽으로 출발(cw 기본값 = 우회전).
- 한 번에 90° 도는 원(지름 약 33cm)이 남쪽 도로(24cm)에 들어가지 않아 나눠 돈다. 계산상 여유는 0.82cm로 빠듯하다.
- 잴 것: 각 정지 위치, 두 번의 회전 뒤 방향, 마지막 회전 때 차체 북쪽 모서리가 안쪽 블록 경계를 넘는지.
- 조정:
  - 정지가 늘 짧으면(앞에서 멈춤) `--stop-lead 0.06`, 늘 지나치면 `--stop-lead 0.2` (기본 0.12)
  - 전진이 출발하지 못하면 `--creep-duty 0.40` (기본 0.36)
- 북쪽 합류(`--start north:S:60`)도 같은 방식이다(여유 1.25cm).

### E5. 전체 임무 (출발 구역부터)
```bash
./run_mission.sh --drive
./send.sh right        # 남쪽 삼거리 전에
./send.sh stop         # 사거리 횡단보도 앞
./send.sh resume
```
- 출발 구역 → 남쪽 삼거리 우회전 → 사거리 → 동쪽 삼거리 합류 → 출발 구역.

## 잘 안 될 때

| 증상 | 확인 / 조치 |
|---|---|
| 출발하지 못함 | 로그 `pwm`이 0.30보다 낮은지 본다. CNN 속도는 1.0으로 고정이다. 배터리 전압도 확인한다 |
| 교차로를 지나쳐 버림 | 로그 `sxy`가 2 이상이면 지도가 위치를 잃은 것이다. 교차로 도착은 sxy가 2 미만일 때만 감지한다. 출발 위치를 더 정확히 놓는다 |
| 회전하다 멈춤 | `traverse_hold_no_fix`가 보이면 지도가 위치를 잃은 것이다(최대 1초 정지 후 진행). 제자리 회전이 돌지 못하면 `--pivot-duty`를 올린다 |
| 회전 후 방향이 틀어짐 | 회전은 지도가 보는 방향 기준이다. 회전 중 지도 위치가 크게 튀었는지 로그 `pose_gated`를 본다 |
| 선을 자주 밟음 | `--turn-duty 0.32`(교차로 근처 감속, 기본 0.34)를 시도한다. 영상과 기록을 남긴다 |
| 교차로 정지 위치가 일정하게 어긋남 | `--stop-lead`로 조정한다(기본 0.12초분 일찍 정지) |
