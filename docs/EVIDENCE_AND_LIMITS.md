# 증거 수준과 실험 해석

## 서로 다른 성공의 의미

| 표현 | 실제로 확인한 것 | 추가로 필요한 것 |
|---|---|---|
| 합성 validation F1 | 지정 tolerance 내 경계 정밀도·재현율 | 다른 실차 환경, 독립 test |
| 2px 참고선 coverage | 일부 표시 선 근처에 검출이 존재 | 전체 false-positive, 표시 오차, 미표시 경계 |
| 정합 통과 | 현재 prior에서 경계점의 55% 이상이 2.5cm 미만, 절대거리 중앙값 1.8cm 이하 | 독립 실차 자세 오차, 정확한 경계 ID |
| 시뮬레이터 완주 | 해당 렌더러·구동 모델의 한 바퀴 | 실차 폐루프, 지연·저출력·배터리·사각 검증 |
| 실차 영상 재생 | 고정된 실제 궤적에서 모델 관측을 비교 | 새 명령을 보냈을 때 나타날 영상·궤적 |
| 사람 경계 | 작성 이력이 불분명한 기존 참고선 또는 Codex의 육안 좌표 | 사용자 검수와 독립 정답. 완전한 oracle로 취급 금지 |

## 제어기 정합 로직

PWM으로 자세를 예측하고, 관측을 카메라 전방 6~35cm의 바닥점으로 변환한다. 점 20개 이상, 전방 분포 폭 5cm 이상이 필요하다. 최대 약 140개를 일정 간격으로 선택하고 지도 거리장을 표본화한다. 2.5cm 미만 점 비율이 55% 이상이고 전체 절대잔차 중앙값이 1.8cm 이하면, 유효점으로 정규화 최소제곱 자세 보정을 수행한다. 이 조건을 벗어나면 기본 외곽 Driver는 즉시 unmatched road edges로 정지한다.

거리장은 가장 가까운 경계까지의 거리이므로 서로 다른 경계나 잘못된 구간과의 일치도 낮은 잔차를 만들 수 있다. 샘플의 공간 분포, 관측 가능한 자세 성분, 지도·투영 오차를 함께 봐야 한다. 소실된 관측을 예측으로 대체해 무제한 주행하는 근거는 없다.

## 추정과 제어의 관계

- GainTracker의 계수는 다음 PWM 운동 예측에 반영된다. 표식의 상대 각도 추정이 입력이다.
- CompensatedDriver/Feedback의 출력계수는 목표 곡률에 필요한 좌우 출력 차이를 조절한다.
- PWM 동일은 바퀴 속도 동일을 의미하지 않는다. 실제 속도 센서가 없다.
- 회전 중심의 고정 기하와 미끄러질 때의 순간 중심은 별개다.
- 표지판 분류, 바닥 표시, 도로 분할, 차량 자세 추정은 서로 다른 출력과 정답이 필요하다.

## 미해결 문제

1. 각 세션의 카메라 외부 파라미터와 실제 인쇄 맵의 오차를 독립 측정하지 못했다.
2. 연속 실차 자세 정답이 없어 정합 잔차 감소를 실차 위치 정확도 향상으로 환산할 수 없다.
3. 가림 물체 클래스의 실제 학습 정답과 충분한 실차 경계 라벨이 없다.
4. 경계 선택을 바꾼 결과가 삼거리에서 잘못된 출구 선택을 만들지 확인해야 한다.
5. 카메라가 부족한 상황과 모터 저출력 정체가 겹칠 때의 복구·정지 조건이 필요하다.
6. 모델의 Pi 지연, 카메라·표지판 인식 동시 실행 부하와 완전 미션은 검증되지 않았다.

## 외부 제안 검토 근거

시각 피드백은 관측 특징과 목표를 정하고 폐루프 오차를 줄이는 방법이다. 정지 촬영은 흐림 완화 후보지만 사각의 해소나 바퀴 재기동 성공을 보증하지 않는다. [Chaumette 시각 서보 강의](https://homepages.inf.ed.ac.uk/rbf/IAPR/researchers/D2PAGES/TUTORIALS/VisualServoing_Chaumette.pdf)

스키드 모델 계수의 온라인 추정 연구는 존재한다. 해당 연구에는 휠 엔코더 등이 포함되므로 본 프로젝트에 동일 정확도를 적용하지 않는다. [관련 논문](https://arxiv.org/abs/2006.04335)

카메라 노출·게인·화이트밸런스의 실제 API와 값은 설치 버전 및 촬영 metadata로 확인한다. 기록의 50~66.5ms 노출을 예시의 8ms로 바꿀 때 밝기·잡음·필터 광량 손실을 함께 평가한다. [공식 매뉴얼](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf)
