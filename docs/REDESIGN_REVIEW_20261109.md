# 예측 오류를 전제로 한 구조 재설계 · Claude 제안 검토

상태: 설계 제안. 새 제어기를 구현·배포하거나 성능을 검증한 문서가 아니다. 사용자 제공 Claude 제안, 프로젝트 기록, [22개 환경 간섭 시험](../research/real_stress_20261109/FINDINGS.md)을 비교했다. 트랙 전체를 촬영하는 외부 카메라와 ArUco 정답 수집을 전제하지 않는다. 현재는 저장 자료로 진행한다.

## 결론

채택할 중심은 **국소 주행, 구간·미션 판단, 불확실성, 실행 가능성 판단의 분리**다. 세계 지도와 기하는 보존한다. 보이지 않는 코너와 교차로의 연결·폭·차체 회전 공간을 다루려면 여전히 필요하다. 정확한 전역 자세 한 개의 성공 여부가 모든 기능의 실행을 결정하던 연결을 바꾼다.

Frenet 좌표나 칼만 필터로 교체하는 것 자체가 해결책은 아니다. 잘못된 관측의 대응 관계, 서로 다른 가능한 자세, 바퀴 정체, 미션 마지노선을 표현할 수 있어야 한다. 새 숫자를 정할 때도 실측·추정·설계 가정을 구분해야 한다.

## 제안에서 채택·수정할 부분

| 제안 | 검토와 변경 |
|---|---|
| 필요한 판단부터 설계 | 채택. 전역 좌표의 높은 정확도 대신 각 행동이 요구하는 정보를 명시 |
| 국소 관계와 구간 ID 분리 | 채택. 구간 ID도 틀릴 수 있는 가설로 관리. 교차로 횟수만 누적하지 않음 |
| 전역 좌표가 필요 없음 | 표현 방식과 정보 필요량을 구분. 회전 중 차체가 어느 경계에 얼마나 가까운지는 필요하며 이를 상대 좌표로 표현할 수 있음. 사각에서 지도와의 정렬도 필요 |
| 차선 유지 ±1~2cm, 각도 ±2° | 근거 없는 예시를 요구조건으로 채택하지 않음. 도로 18cm, 차량 폭 16cm이면 평행·정중앙일 때도 양옆 1cm뿐. 전장 24.5cm의 외접 직사각형으로 보면 2° 기울 때 가로 투영 폭은 약 16.85cm. 실제 윤곽·캘리브레이션·제동 여유를 함께 계산 |
| 후보별 s,d,psi와 sigma | 채택하되 상관관계를 담은 공분산 또는 범위를 유지. 같은 구간 안의 서로 떨어진 진행 위치도 별도 후보로 남길 수 있어야 함 |
| 후보별 칼만이 가장 적합 | 구현 후보일 뿐 확정하지 않음. 정체/이동처럼 분리된 경우를 하나의 평균으로 합치면 실제로 가능성이 낮은 중간 위치가 됨. 후보별 EKF와 구간별 격자/범위 표현을 저장 자료로 비교 |
| 차선은 d,psi만, 가로 표식은 s만 갱신 | 단순화가 과함. 평행 직선 경계에는 종방향 제약이 약하지만 접속부·끝점에는 정보가 있음. 가로 표식의 방향·끝점은 yaw·횡위치도 제약. 관측 함수의 실제 민감도로 정보가 있는 방향만 갱신 |
| 마스크 왼쪽/오른쪽 끝 = 좌우 경계 | 교차로·가림에서는 성립하지 않음. 연결된 도로 마스크에도 여러 출구가 있음. 가까운 경계 조각을 유지하고 선택한 출구에 대한 좌우 대응을 후보로 관리. 최외곽 픽셀을 자동으로 차선으로 확정하지 않음 |
| 잘못된 대응은 관측 단계에서만 막을 수 있음 | 과장. 의미 분류·기하적 호환성·강건 비용·시간적 대응·후보 검증이 공동으로 다뤄야 함 |
| sigma에 비례한 게이트 | 채택하되 sigma 자체의 신뢰성을 검증. 불확실성을 크게 주면 모든 후보가 허용되는 문제가 생김. 관측의 의미와 후보 식별 가능성도 별도로 검사 |
| 3~5프레임 연속이면 큰 보정 수용 | 고정 규칙으로 채택하지 않음. 같은 반사·물체는 여러 프레임에서 일관되게 틀릴 수 있음. 독립 단서, 카메라 이동에 맞는 특징 변화, 대응 ID 등을 검토. 이전 96장 검사는 각 prior를 따로 검색했으므로 시간 일관성이 검증된 추적기는 아님 |
| 한쪽 경계에서 일정 간격 주행 | 직선·해당 도로폭·경계 ID가 확인될 때 조건부로 사용. 18/21/24/26cm 폭 전환과 삼거리에서는 고정 간격 사용 금지. 한쪽 관측을 완전한 양쪽 관측으로 둔갑시키지 않음 |
| 불확실하면 감속 | 방향은 타당하나 저출력에서 바퀴가 멈추거나 늦게 움직인 기록을 반영. 속도를 0까지 연속 감소시킬 수 있다고 가정하지 않음. 검증된 구동 구간과 정지를 구분 |
| 멈춘 뒤 좌우로 탐색 | 필수 동작으로 넣지 않음. 차체 전체가 쓸고 지나갈 공간을 확인할 수 있을 때만. 미끄러짐과 불확실성을 더 키울 수 있음 |
| 출구 정렬로 회전 종료 | 채택하되 출구 ID·횡위치·차체 뒤쪽 통과도 확인. 방향만 평행해도 잘못된 출구나 도로 가장자리일 수 있음 |
| 표식이 보이면 실행 | 마지노선 전에 실행해야 하므로 단순 가시성 이벤트로 부족. 거리·지연·실행 시간·정지거리와 올바른 표식 ID 필요 |
| ArUco 정답 수집 우선 | 현 여건의 선행조건에서 제외. 정확도 1cm 이내를 장비·보정·가림 검증 없이 약속할 수 없음 |

## 요구조건을 물리 공간에서 표현

도로폭 W, 차량 폭 B, 전장 L, 중심 횡오차 d, 도로 대비 각도 psi일 때 직선에서 외접 직사각형의 가로 폭은 다음과 같다.

`B_eff = B*abs(cos(psi)) + L*abs(sin(psi))`

이 근사에서 `abs(d) + B_eff/2 + m <= W/2`가 필요하다. m은 임의의 새 상수가 아니라 차체 윤곽·지도·카메라 추정 오차와 실행 지연에 남겨야 할 여유다. 이 계산은 직선의 단순 외접 모형이며 곡선에서는 실제 사진 윤곽을 경로 전체에 걸쳐 변환해 검사한다. 같은 ±2cm 오차도 26cm 외곽과 18cm 내부 도로에서 의미가 다르다.

신호나 STOP의 실행 시점도 임의 픽셀선으로 끝내지 않는다. 지정 기준점(예: 차체 앞끝)부터 표식까지의 남은 거리 하한이, 가능한 속도에서의 지연 중 이동량·정지/행동 완료거리 상한과 어떻게 비교되는지 판단한다. 실제 정지거리 상한은 아직 검증되지 않았으므로 초기에는 알려진 값처럼 쓰지 않는다.

## 새 구조의 모듈 계약

| 모듈 | 입력 | 출력과 책임 |
|---|---|---|
| 프레임·명령 기록 | 카메라 영상/metadata, 명령 시각 | 같은 시계 기준의 프레임·노출 구간·명령 이력. 명령을 실제 속도라고 표기하지 않음 |
| 시각 관측 | 현재 및 이전 영상, 카메라 보정 | 경계 조각, 표식 종류/위치/방향, 가림·미관측 영역, 불확실성 및 추적 ID 후보. CNN은 이 단계의 선택지 |
| 국소 도로 해석 | 경계 조각, 도로폭 후보, 출구 후보 | 차량 기준의 도로 통로와 국소 경로 후보. 옆 오차뿐 아니라 전방 곡률·폭·가시 구간을 포함 |
| 구간·자세 가설 | 지도 그래프, 명령, 관측 | 진입 도로/회전 경로/출구 가설과 각 상태 범위. 하나의 최선값만 강제로 반환하지 않음 |
| 미션 관리 | 표지 큐, 표식 추적, 구간 가설 | 목표 출구, STOP/SLOW/HORN 상태, 중앙 교차로 신호 행동과 완료 여부 |
| 경로·명령 선택 | 국소 경로, 지도 후보, 미션, 차체 윤곽, 구동 응답 범위 | 가능한 명령 중 경계 침범과 잘못된 출구 선택을 피하는 명령. 행동을 확정할 수 없으면 보류 |
| 실행·재관측 | 선택 명령, 전원/통신 상태 | 적용 명령 기록, 응답 확인, 예측 실패 상태 분류. 관측 거부가 곧 영구 정지가 되지 않도록 분리 |

지도의 좌표를 지우지 않는다. 각 후보의 구간 좌표 `(s,d,psi)`를 지도의 `(x,y,theta)`로 변환해 차체·경로 여유를 계산할 수 있다. 교차로 전체에는 단일 Frenet 축을 강제하지 않고 진입로와 가능한 회전 경로마다 기준 곡선을 둔다.

### 1. 관측과 예측이 충돌하면 양쪽을 의심한다

관측을 prior와 비교하기 전에 영상 자체에서 후보를 생성한다. 그 뒤 다음 가설을 비교한다.

- 예측은 가깝고 일부 경계 조각이 잘못 검출됨.
- 관측은 설명 가능하지만 차량 운동이 예상과 달랐음.
- 서로 다른 출구/표식/구간과 대응할 수 있음.
- 지금 자료로 판단할 수 없음.

예측이 기존 후보를 확장하는 역할은 하지만, 기존 예측 범위 밖이라는 이유만으로 독립적인 관측 후보를 영구 제거하지 않는다. 반대로 잔차가 작다는 이유만으로 새 후보를 채택하지 않는다. 잘못된 후보를 택한 기존 시험의 12.48→16.26cm 악화가 회귀 검증 대상이다.

CNN 점수가 높다는 이유만으로 관측이 정확하다고 판정하지 않는다. 검증 자료에서 오검출·위치 오차와 점수의 관계를 확인하고, 가림과 학습 분포 밖의 입력을 표현할 여지를 남긴다. 불확실한 픽셀을 반드시 도로/도로 밖 한쪽으로 확정하면 같은 문제가 관측 단계에서 반복된다.

### 2. 믿음 상태는 이동 모드와 구간 안의 모호성도 포함한다

개념적인 상태는 다음과 같다.

`hypothesis = {진입/출구 경로 ID, 표식 대응 후보, 정체/이동 모드, (s,d,psi), 공분산 또는 범위, 근거 이력}`

구간 ID 하나에 가우시안 하나만 두면 같은 직선에서 멀리 떨어진 두 위치 후보를 놓칠 수 있다. 관측이 부족한 종방향은 넓은 구간 또는 여러 봉우리로 유지한다. 후보 수 제한 때문에 버린 가설을 확실히 틀렸다고 취급하지 않고, 표현하지 못한 가능성이 있음을 기록한다. 초기부터 다중 후보를 표현할 인터페이스를 두되 실제 유지 개수는 계산량과 모호성 자료로 정한다.

단순 프레임별 독립 잡음 외에 지속적인 속도 편향을 고려한다. 바퀴 정체는 이동량 0 가능성을 포함하지만, 이동량을 무조건 0~명령값으로 제한해서도 안 된다. 실제로 예측보다 더 이동할 수 있다. 0.65~0.72, 1.0~1.27 등의 과거 값은 초기 사례이지 검증된 전체 오차 상한이 아니다.

### 3. 국소 조향도 한 쌍의 숫자로 축소하지 않는다

직선에서 d,psi를 이용한 폐루프 조향은 좋은 시작이다. 하지만 코너에서는 앞쪽 경로의 곡률, 비대칭 폭과 차체 후미의 이동도 필요하다. 카메라 이미지의 중앙이나 두 선의 픽셀 평균을 목표로 하지 않고, 차량 기준으로 변환된 도로 통로 안의 경로를 따른다. 지도는 가려진 경계의 구조적 가설을 제공한다.

여러 자세·출구 후보가 같은 좌회전 명령을 허용한다면 정확한 위치 하나를 고르지 않고 그 공통 명령을 실행할 수 있다. 후보에 따라 좌회전과 우회전이 갈리면 평균 조향으로 직진하지 않고 결정을 보류한다. 가능한 자세와 구동 응답에서 같은 명령을 실행했을 때 차체 윤곽이 지나갈 영역을 검사한다. 이 가능성 범위가 실제를 포함한다는 검증 없이 절대 안전 보장이라고 부르지 않는다.

### 4. 모드는 명령 가능성으로 전환한다

| 상황 | 처리 |
|---|---|
| 종방향은 불명확하지만 현재 직선의 도로 통로가 보임 | 국소 추종 가능. 교차로가 없다는 근거가 사라지는 시점에는 같은 결론을 연장하지 않음 |
| 한쪽 경계만 보이고 경계 ID·도로폭이 일관됨 | 조건부 추종. 반대 경계는 추정이라는 표시와 불확실성을 유지 |
| 경계가 잠깐 사라짐 | 마지막 관측·지도·운동 범위에서 가능한 움직임이 남아 있는 동안만 진행. 미션 마지노선도 함께 검사 |
| 후보별 안전한 진행 방향이 다르거나 허용 명령이 없음 | 정지하고 다시 관측. 관측 실패가 아니어도 정지가 필요할 수 있음 |
| 정지 후 관측 개선 | 출구/위치 후보를 재평가하고 경로 진행 상태를 별도로 정리한 뒤 재개 |
| 정지 후에도 판단 불가 | 정지 유지. 공간을 확인할 수 없는 탐색 회전을 강제하지 않음 |

작은 PWM으로 감속하는 것이 항상 가능한 차량이 아니다. 초기에는 기존 구동 시험을 바탕으로 움직임을 기대할 수 있는 명령 구간과 정지를 구분하고, 실제 반응이 없는 경우를 별도 상태로 남긴다. 짧은 구동과 정지를 반복하는 방법도 재기동 실패와 지연을 따로 시험해야 한다.

### 5. 미션은 거리와 ID를 같이 본다

- 방향 표지는 다음 관련 갈림길의 출구 선택에 연결한다. 해당 출구가 가능하다는 확인 없이 표지 한 번으로 분기를 확정하지 않는다.
- STOP/SLOW/HORN은 올바른 핑크 점선의 마지노선 전에 완료해야 할 동작으로 예약한다. 표식이 화면에서 사라져도 이미 예약된 동작을 취소하지 않는다. 같은 선을 여러 번 검출해 중복 실행하지 않도록 상태를 보관한다.
- 중앙 사거리는 내 진입로의 횡단보도와 오른쪽 신호등을 연결한다. 외곽 횡단보도와 혼동하면 안 되므로 구간 정보가 필요하다. 빨간불 정지 후 우회전과 신호 재개 조건은 과제 규칙에 따라 별도로 둔다.
- 미션 실행 이벤트, 구간 전이, 자세 재보정을 따로 기록한다. 자세가 7cm 고쳐졌다고 7cm 주행하거나 표식을 통과한 것으로 세지 않는다.

## 칼만·게이트와 시간 처리에서 주의할 점

칼만 계열의 관측 일관성에는 예측 불확실성뿐 아니라 관측 오차도 들어간다. 관측 함수의 야코비안을 H, 예측 공분산을 P, 관측 공분산을 R이라 하면 `S=H P H^T+R`, 혁신을 r이라 하면 비교량은 `r^T S^-1 r`이다. 큰 sigma만 주면 신뢰도가 높아지는 것이 아니다. R, Q와 오차 분포가 틀리면 이 숫자도 신뢰 가능한 확률이 아니다. 같은 경계의 많은 픽셀과 연속 프레임을 독립 측정으로 중복 계산하지 않는다. [OpenCV KalmanFilter 공식 문서](https://docs.opencv.org/4.13.0/dd/d6a/classcv_1_1KalmanFilter.html)

관측 시각은 카메라 metadata 정의를 확인한다. 현재 공식 Picamera2 문서는 SensorTimestamp를 첫 픽셀 readout 시각으로 설명하며, 첫 픽셀 노출 시작은 노출시간을 빼서 구한다. 첫 픽셀의 노출 중간 근사는 `SensorTimestamp − ExposureTime/2`이지만 행별 읽기 시차가 있는 영상 전체의 정확한 시각과 같지는 않다. 설치 버전·단위·시계와 영상 전처리를 확인하고, 영상 시점에 보정한 뒤 명령 이력으로 현재 시각까지 예측하는 방식을 검토한다. [Picamera2 공식 매뉴얼 §6.4.1 및 SensorTimestamp](https://datasheets.raspberrypi.com/camera/picamera2-manual.pdf)

## 외부 카메라 없이 진행할 검증

ArUco/천장 카메라를 필수 조건에서 제외한다. 향후 외부 촬영이 가능하더라도 일부 코너나 짧은 구간만 측정할 수 있고, 전체 트랙을 한 번에 볼 필요는 없다. 그러나 현재 그런 장비가 있다고 가정하지 않는다. 차량 카메라가 바닥의 마커를 보는 방법은 운행 입력을 추가하는 것이며 자동으로 독립적인 실차 정답이 되지는 않는다.

현재 자료로 할 수 있는 일:

1. 기존 22개 시험을 회귀 시험으로 고정한다. 새 값에 맞춰 평가 조건을 계속 바꾸지 않는다. 반사 위치·지속 시간, 지속 편향, 교차로 폭, 카메라 각도 오차 등 별도 조건은 개발용과 보류 평가용으로 분리한다.
2. 실제 96프레임과 기존 영상에서 경계 조각·표식 대응 후보를 시각화한다. 작성 이력이 불명확한 참고선을 독립 정답으로 쓰지 않는다. 검수된 작은 라벨 집합을 별도로 만든 뒤 관측 선택을 평가할 수 있다.
3. 새 추정기와 제어기는 우선 기록 영상에서 명령을 계산만 한다. 이 방식으로 실제 완주나 새로운 명령의 효과를 검증했다고 주장하지 않는다.
4. 시뮬레이션에서는 침범·잘못된 출구·미션 마지노선 위반·회복 여부·위치 오차·불확실성 범위의 정답 포함 여부를 함께 평가한다. 멈추지 않았다는 결과만 성공으로 세지 않는다.
5. 차량을 다시 확보하면 알려진 시작/종료 기준점이나 특정 표식 앞의 정지 위치처럼 부분 측정부터 한다. 전체 연속 자세 정답이 없으면 실차 절대 위치 정확도 주장에는 그 한계를 남긴다.

## 구현 순서

1. 관측 표현과 기록 인터페이스: 경계 조각, 의미·대응 후보, 가림/미관측, 시간과 단위. 현재 HSV와 CNN을 같은 계약으로 비교.
2. 직선 구간의 국소 도로 추종과 후보 상태: 종방향 모호성이 d/psi 제어를 불필요하게 끊지 않는지 확인. 출력 보상과 예측계수 동시 학습은 처음에는 고정해 원인 분리를 쉽게 함.
3. 외곽 코너와 내부 교차로의 경로 후보·차체 여유 검사: 한쪽/양쪽 경계 소실, 폭 전환과 잘못된 출구 선택을 포함.
4. 표식 대응·미션 마지노선·진행 상태: 중앙 사거리와 외곽 횡단보도를 구분하고 재위치 보정과 통과 이벤트를 분리.
5. 관측 기반 구동 응답 갱신과 제한된 예측 주행: 관측이 구별 가능한 상황에서만 갱신하고 별도 조건으로 평가.

모든 단계의 수치에 출처를 붙인다: 물리 실측, 관측 오차로 추정, 개발용 가정, 미확인. 현재 자료로 정당화할 수 없는 허용 오차나 확률을 확정값으로 만들지 않는다.
