# 2026-11-10 실차 시험과 지도 수정

## 실제 실행 결과

한 바퀴 완주는 달성하지 못했다. 새 어댑터로 실차에 PWM을 전달했고, 카메라·추정·계획·출력을 기록했다. 진행 거리는 지도 추정치이며 독립 실측 주행거리가 아니다.

- 최초 5초 제한 시험: 약 1.2초 동안 양수 PWM 출력 뒤 `observation_budget_exhausted`. 80프레임 모두 정합은 observed였다. 촬영 시각과 처리 시각이 같을 때만 거리 예산을 초기화하던 버그를 수정했다. 신규 관측 시각이 들어오면 초기화하고, 반복 프레임이나 오래된 관측으로는 초기화하지 않는다.
- 출발 위치를 사용자가 원래 자리로 옮겼다는 메시지가 실행 중 도착했다. 직전 정지 위치로 초기화했던 시험을 SIGINT로 중단했다. 사용자가 재배치·손 뗌을 확인한 뒤 다시 실행했다.
- `live_20261110_182520`: 추정 약 107cm 진행 후 첫 코너 앞에서 계획 보류. 사용자는 바퀴가 전혀 벗어나지 않았고 코너 앞 약 3cm라고 확인했다. 평균 자세의 추정 침범 약 2.3cm와 실제 관찰이 불일치했다. 이를 실제 침범으로 보고하지 않는다.
- `live_20261110_182926`: 그 위치에서 추정 약 28cm 더 진행해 코너에 진입했다가 보류. 후보의 최소 여유가 양수여도 기존 목표 2.5mm보다 작아서 탈락했다.
- `live_20261110_183105`: 코너에서 추가 진행 후 한 프레임의 센서→결과 지연 405.7ms 때문에 종료. 이후 늦은 결과는 버리고 0출력을 보내며 다음 프레임을 기다리도록 어댑터를 수정했다. 독립 출력 watchdog 0.5초는 유지한다.
- 사용자는 코너에서 오른쪽 앞바퀴가 돌지 않고 차체 뒤쪽만 끌려 붙는 현상을 관찰했다. 실제 로그에는 안쪽 PWM 약 12%와 바깥 약 35%가 있다. 특정 바퀴의 실제 속도는 기록되지 않았다. 현재 GPIO 어댑터는 좌우 두 채널만 사용한다.
- `start_threshold_20261110_183615`: 정지 상태에서 양쪽 30%, 35%, 40%를 각 1초 인가, 단계 사이 정지. 자동 종료·최종 출력 0. 사용자는 **30%부터 네 바퀴 모두 출발**했다고 확인했다. 30%가 정확한 최소치라는 뜻도, 코너 부하에서도 충분하다는 뜻도 아니다.

## 실험판과 기본 설정의 구분

현장 어댑터 원본은 저장소 밖 `field_validation_20261110/live_outer_trial.py`와 Pi의 별도 배포 폴더에 있다. 게시 시 마지막 스냅샷을 [field_experiments/20261110](../field_experiments/20261110/README.md)에 추가했다. 기본 runtime.json을 현장 값으로 전부 덮어쓰지 않았다.

현장 판정은 bounded_prefix, 후보 오프셋 ±4cm, 목표 여유 0cm, 평균 자세 침범 상한 3cm, 불확실성 대표 자세 상한 5cm다. 대표 자세마다 진행 중 악화 허용은 최대 0.02cm이며 구간 끝에서는 초기보다 악화되지 않아야 한다. 평균 침범 시 복귀 조건은 유지한다. 모두 현장 임시 정책이지 검증된 확률적 안전 보장은 아니다. 불확실성을 정확히 보정한 값도 아니다.

`--rolling-floor .30` 프로필을 추가했다. 최소 PWM 30%, 최대 60%, 선호 속도 4.8cm/s, 월드 모드 계획 검사 상한 8cm/s. 모델상 곡률을 유지하기 위해 양쪽 PWM을 함께 키우되 출력·속도·각속도 한도를 넘으면 `deadband_path_infeasible`로 정지한다. 최소치만 개별 클리핑해서 회전비를 바꾸지 않는다. 후속 local 모드 실주행에는 적용했지만 이 프로필로 코너를 통과하거나 60% 구간을 검증한 것은 아니다. PWM→속도 모델은 기존의 임시 선형 모델을 유지하며 실제 바퀴 속도 보정이 완료됐다고 주장하지 않는다.

## 별도 국소 관측 모드: 구현 범위와 실제 실패

사용자가 전역 위치를 모른다는 이유로 출발 자체를 막는 문제를 지적한 뒤, 빠른 시험을 위해 `local_corridor.py`와 `Runtime.local_mode`를 추가했다. 그러나 이것은 원래 합의한 세 번째 구조 전체의 완성이 아니다. 사용자가 이 점을 확인했으며, 구현 범위 차이를 충분히 설명하지 않고 실행한 점을 정정했다.

- 재사용: HSV/카메라 보정/BEV, Pure Pursuit, 출력 하한·포화·변화율, GPIO 어댑터와 정지 장치.
- 새 경로: 가까운 행부터 도로 경계 사이 중앙을 추적하고 강건 이차식으로 맞춘다. 안쪽 개구부는 바깥 경계와 폭으로 보완한다. 이 보완은 관측 사실이 아니다.
- 우회/미구현: 전역 지도 정합, 실제 지도 코너 형상의 국소 정렬, 구간 ID 갱신, 사건 기반 교차로 진입 판정, 표지판 방향 선택과 전체 미션 통합, 차체 쓸림·장애물 충돌 보장.
- 로그의 `next_known_junction_options`는 방향에 따른 고정 설명값이며, 실제 다음 교차로를 인식하거나 위상 상태를 갱신한 결과가 아니다.
- 월드 자세와 진행거리는 적용 PWM의 예측값뿐이다. local 모드는 이를 한 바퀴 완료 판정에 사용하지 않고 시간 상한과 사용자 정지 버튼을 사용했다.

`live_20261110_185902`에서 실제 출력이 나와 주행했지만 코너 앞에서 멈췄다. 사용자는 코너에 가까워져도 직진했다고 보고했다. `local_corridor_inconsistent`, 이어서 `local_boundaries_missing`가 발생했고 8초 보류 뒤 최종 0출력으로 종료했다. [로그 요약·실행 코드 해시·설정](evidence/field_local_20261110.json)을 참조한다. 출발 성공을 완주 성공으로 바꾸어 설명하지 않는다.

이후 Pure Pursuit의 10cm 고정 목표가 실제 관측 시작점(새 출발 영상에서 약 23cm)보다 가까운 보간 구간에 놓이는 문제를 수정했다. `PathDecision.lookahead_cm`를 추가해 관측 시작점까지의 경로 길이+5cm를 목표로 사용하고, 첫 행 탐색의 측방 범위를 넓혔다. `dry_20261110_190122` 35프레임은 GPIO 없이 종료했다. **수정 후 코너 실주행은 하지 않았다.** 기본 월드 모드의 10cm 목표는 별도 지정 없으면 그대로 유지한다.

향후 과제는 이 실험 모드에 보정을 계속 덧붙이는 것이 아니라, 구간·진행 방향으로 지도 경로 형상을 고르고 관측에 국소 정렬하는 원래 원칙을 실제 코드에 연결하는 것이다. 현재 게시 시점에 그 작업은 완료되지 않았다.

## 사용자 확인 지도 / 새 출발 구역

좌우·위아래는 사용자가 올린 평면도 기준. 오른쪽 세로도로 아래에는 핑크 점선이 없고, 오른쪽 아래 코너의 점선은 아래 가로도로에만 있다. 잘못된 동쪽 아래 점선을 삭제했다. 평면도에 보이는 위쪽 가로도로 오른쪽 점선을 추가했다. 후자의 세부 좌표는 기존 좌우 대칭 치수를 재사용했고 새 실측값은 아니다.

빨간 실선 두 개는 오른쪽 위 핑크 점선에서 아래로 98.5cm, 128cm. 기존 위쪽 가로도로의 빨간선을 오른쪽 세로도로로 옮겼다. 기존 위쪽 핑크선 y=65cm를 기준으로 빨간선 y=-33.5, -63.0cm다. 선 길이 16cm와 도로 절대 좌표는 기존 가정을 유지한다.

출발 구역은 두 빨간선 사이이며 정확한 한 점에 배치하지 않는다. 차체 길이 24.5cm, 구역 길이 29.5cm. 평행하고 차체 전체가 구역 안에 있다는 조건에서 차체 중점 y는 [-50.75,-45.75]cm다. 차축 중점은 차체 중점과 2.25cm 차이가 난다. 위를 보면 반시계(ccw, yaw=0), 아래를 보면 시계(cw, yaw=π). `start_region.py`는 구역 중앙을 추정 초기값으로만 쓰고 배치 폭과 기존 지도 오차를 반영한 초기 공분산을 만든다. yaw 8도 σ는 임시 가정이며, 회전된 차체에서는 x/y/yaw 가능 범위가 결합되므로 이 독립 가우시안은 근사다.

사용자는 현재 새 구역에서 위쪽을 바라본다고 확인했다. `dry_20261110_184548`는 모터 없는 60프레임 시험이며 모두 prediction_only였다. 각도 seed ±0.25rad 및 표식 제거 비교에서도 저장된 첫 프레임 정합은 통과하지 않았다. 현재 경계 조각과 지도 대응의 문제를 추가 검토해야 하며 새 구역 출발 성공으로 보고하지 않는다.

## 검증과 보존

게시 직전 전체 자동 시험 **82개 통과**. 국소 모드의 관측 없음·지연 프레임 정지, T 개구부 직진, 관측 안쪽 목표점, 출력 하한, 구역 초기값 및 관측 거리 예산 회귀를 포함한다. 합성 마스크 시험은 실차 코너 성공 증거가 아니다. 하드웨어 시험을 일반 단위시험으로 실행하지 않았다.

현장 이미지·로그·당시 배포 코드는 노트북의 `field_validation_20261110/field_trials_20261110.tar.gz`로 복사했다(첫 출력 하한 시험 이전 시점). 이후 최소 출력 시험과 새 출발 구역 시험 원본은 Pi에 남아 있으며, 새 구역 첫 원본 이미지와 JSONL은 노트북에도 복사했다. 원래 자료와 새 지도 해시를 혼동하지 않는다.
