## 바로 학습 정답으로 쓰지 않는 이유와 활용 위치

- CSV의 `offset_cm`, `heading_deg`는 독립 위치 정답으로 취급하지 않는다. 기존 색 대비 주행 코드가 영상에서 계산한 추정·제어 값과 구분해야 한다.
- `left/right`도 실제 바퀴 속도가 아니다. 로그 생성 코드의 버전과 최종 모터 적용 경로를 대응시킨 뒤 명령 이력으로 사용해야 한다.
- 당시 `lane_drive.py` 사본은 카메라 영상을 받은 뒤 처리한 시점에 `t`를 기록하고, 180도 회전한 원시 영상을 저장한다. 모든 회수 세션이 그 사본과 동일 버전인지는 미확인이다. 저장 frame ID가 같다는 사실만으로 카메라 노출 시각과 PWM 적용 시각이 정밀하게 정렬됐다고 볼 수 없다.
- params JSON 두 개를 해석하지 못했다. `runs/20261104_200803/params.json`, `runs/20261104_195143/params.json`은 노트북 원본 목록에서도 0바이트였다. 복사 과정에서 새로 생긴 누락으로 세지 않는다. 그 묶음의 보정·실행 설정을 임의로 채우지 않는다.
- 과거 주행 동작에는 레거시 코너 처리가 포함될 수 있다. 새 부드러운 코너링 행동의 정답으로 그대로 복제하지 않는다.

우선 활용처는 **기존 FloorVO·지도 관측의 실제 영상 재생 점검, 반사/가림에서의 유효 관측 분석, PWM 명령과 영상 움직임의 시간 대응 검토**다. hyb4 경로 정답과 복원 행동 데이터는 별도 기준으로 마련해야 한다. 이번 회수로 새 CNN 학습이 자동으로 시작되지는 않는다.
