# 11월 10일 플래너 판정 비교

경계 가중치 수정 후 실차 정지 로그의 14/40 경로 보류를 조사했다. 실제 모터는 가동하지 않았다. 입력은 `stationary_20261110_173903`의 보정된 자세·공분산·시각을 그대로 고정한 것이다. 새로운 위치 추정이 같은 결과를 만들 것이라는 가정으로 비교하지 않았다.

## 직접 원인

첫 보류인 26번 프레임에서 28cm 경로의 offset=-1cm 후보는 곡률 0.02216/cm로 제한 0.14/cm 이내였다. 하지만 격자 거리장으로 계산한 최소 여유 0.249455cm는 기준 0.25cm보다 약 0.000545cm(0.00545mm) 작아 탈락했다. 거리장에는 별도로 3.54mm의 수치 오차 차감이 포함되어 있다.

다음 16cm 후보들은 차체 여유로 탈락했다. 10cm와 6cm에서는 같은 횡방향 복귀를 더 짧게 하려고 곡률이 커져 모두 탈락했다. 최종 로그의 곡률 탈락과 최초 긴 경로의 거리 탈락은 서로 다른 단계다. 모든 단계·후보의 판정 값을 이제 기록한다.

정지 상태가 곧 경로 존재를 의미하지는 않는다. 실제 경계 위치·물체·미션·운동 제약에 따라 정지 중에도 경로가 없을 수 있으므로, 40/40을 일반적인 정답으로 놓지 않는다. 이번 자료에서는 정밀 거리만 적용해도 40/40이 나왔다.

## 세 가지 판정 비교

같은 Pi, 같은 저장된 자세 40개를 사용했다. 경로 계산만의 시간이며 관측·추정·YOLO·모터 지연은 제외된다. 최초 3회는 시간 집계에서 제외했다.

| 설정 | tracking | 보류 | 경로 계산 p95 |
|---|---:|---:|---:|
| legacy_full + grid_lower_bound | 26 | 14 | 64.0ms |
| legacy_full + exact | 40 | 0 | 170.7ms |
| bounded_prefix + exact | 40 | 0 | 68.5ms |

`replay_planner.py`로 재현한다. 이 비교는 실주행이나 새로운 영상 전체 처리의 검증이 아니다.

추가로 같은 원본 40장을 Pi에서 관측→추정→bounded_prefix 경로→가상 제어까지 다시 처리했다. 40/40 tracking, 초기 3회 제외 전체 처리 중앙값 112.3ms, p95 118.3ms였다. 이미 메모리에 읽은 사진이므로 카메라 수신 대기·파일 읽기·YOLO·실제 모터 반응은 제외된다. [Pi 전체 처리 비교 근거](../drive_v3/evidence/planner_full_runtime_pi_20261110.json)를 참조한다.

## bounded_prefix 실험 정책

짧은 실행 구간 길이 C는 다음과 같이 계산한다.

```
v_bound = 목표속도 × 1.5
C = v_bound × (재계획주기 + 지연 + 관측나이)
    + v_bound² / (2 × 감속도) + 추가거리
```

현재 기본 대입값은 재계획주기 0.2초, 지연 0.15초, 감속도 12cm/s², 추가거리 0.5cm다. 속도 상한계수·지연·감속도는 실측으로 보장된 값이 아니다. 따라서 C는 검증된 안전거리라는 의미가 아니다.

- C까지는 각 남은 가설의 평균 및 6개 공분산 축 표본을 검사한다. 표본은 불확실성 전체를 덮지 않는다.
- C 이후에는 각 가설의 평균 자세에서 경로 전체를 검사한다. 다른 가설의 평균 경로도 무시하지 않는다.
- 모든 거리는 해석식으로 계산하지만 차체/경로는 여전히 이산 표본이다.
- 여유가 이미 목표보다 작은 자세 표본은 자기 출발 여유보다 더 악화될 수 없다. 표본마다 비교하므로 전체 최악값만 유지하면서 다른 표본이 침범하는 경우를 거부한다.
- 목표 여유 위에서만 0.05cm 수치/판정 여유를 허용한다. 기준 아래에서 재계획마다 0.05cm씩 악화되는 누적 허용은 하지 않는다.
- 최대 침범 0.5cm를 초기 실험 한도로 둔다. 과제에서 허용된 최대치가 아니라 비교용 설정이다. 더 큰 침범은 거부한다.
- 명목 자세가 이미 침범한 경우 짧은 구간 끝에서 최소 0.05cm 개선하거나 목표 여유에 도달해야 한다. 긴 구간 끝에서도 개선/정상 조건을 확인한다.
- 관측된 도로 경계에도 작은 침범 한도를 적용한다. 도로 경계와 실제 물체를 같은 개념으로 취급하지 않는다. 현재 인터페이스에는 물체 점유영역 충돌 검사 입력이 없으므로 물체 회피를 구현했다고 주장하지 않는다.
- 미션 보류, 오래된 관측, 과도한 불확실성, 곡률 제한은 유지한다. 아무 조건에서나 계속 움직이는 정책이 아니다.

기본 설정은 `legacy_full`에 정밀 거리를 적용한 비교판이다. `bounded_prefix`는 명시적으로 선택하는 실험 옵션이다. 운동 잡음 Q와 추정기 가중치는 이번 플래너 비교에서 변경하지 않는다.

## 자동 검사

69개 통과. 새 검사는 작은 기존 침범에서 복귀, 표본별 악화 감지, epsilon 누적 방지, 큰 침범 거부, 명목 침범의 개선 요구, 속도·지연에 따른 C 증가, 정지 가능한 구간보다 짧은 후보 거부를 포함한다.

명령 예:

```
python -m drive_v3.replay_planner <정지_기록_폴더> --output <새_결과_폴더>
python -m drive_v3 simulate --planner-policy bounded_prefix --direction ccw --seconds 220 --output <새_결과_폴더>
```

시뮬레이터는 기존 평가 규칙인 실제 가상 여유 -0.25cm 아래에서 조기 종료한다. 이번 정책의 허용 침범 0.5cm와 다르므로, 침범 후 복귀 성능을 전부 평가하는 시험은 아니다. 성공률을 높이기 위해 기존 종료 기준을 몰래 바꾸지 않았다.

## 기본 양방향 폐루프 결과

이상적인 구동 응답·기본 합성 영상·dt=0.2초·최대 220초 조건으로 검사했다. 네 실행 모두 한 바퀴 약 646cm를 완료했고 같은 코드 해시 `a9762afc…`를 사용했다. 실행 중 소스 변경은 없었다.

| 정책 | 방향 | 완주 시뮬레이션 시각 | 실제 가상 차체 최소 여유 |
|---|---|---:|---:|
| 정밀 거리 + 전체 검사 | 반시계 | 137.0초 | 1.724cm |
| 정밀 거리 + 전체 검사 | 시계 | 137.0초 | 1.730cm |
| 정밀 거리 + bounded_prefix | 반시계 | 137.6초 | 1.687cm |
| 정밀 거리 + bounded_prefix | 시계 | 137.6초 | 1.695cm |

작은 침범을 허용해서 이 기본 완주를 얻은 것은 아니다. 네 경우 모두 실제 가상 차체의 침범은 없었다. bounded_prefix는 이번 조건에서 정밀 전체 검사보다 완주 성능이 우수하다는 증거가 없고, Pi의 저장 자세 재생에서 계산량을 줄인 이점이 확인됐다. 심한 운동 오차·교차로·빛반사·가림·실차 움직임은 이 네 실행에 포함하지 않았다.

노트북의 동시 시뮬레이션 실행시간은 제어 dt에 반영되지 않는다. 따라서 시뮬레이션 완주로 Pi의 실제 제어 지연 대응까지 검증하지 않는다. [네 실행 결과와 해시](../drive_v3/evidence/planner_loops_20261110.json)를 참조한다.
