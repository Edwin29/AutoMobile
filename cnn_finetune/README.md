# A5b 미세조정 계획 (A안) — 2026-11-11

팀 CNN A5b를 우리 시뮬레이터(bench)에서 추가 학습해 코너링과 안정성을 보강한다. **계획 문서이며 아직 구현 전이다.** 진행하면서 이 폴더에 코드와 결과를 추가한다.

## 1. 왜 하는가

실차 기록(2026-11-11, [drive_v4/field_runs/hyb2m_20261111](../drive_v4/field_runs/hyb2m_20261111/README.md))과 현장 관찰에서 두 가지 문제가 보였다.

1. **코너가 고르지 않다.** CNN 출력 자체는 프레임마다 거의 변하지 않았다(중앙값 0.002). 그런데 코너 프레임의 54~59%에서 팀 변환(DutyMixer)이 안쪽 바퀴에 출발 문턱(0.30)보다 낮은 값을 줬다. 바퀴가 섰다 돌았다 하면서 실제 회전이 CNN 의도와 어긋났다.
   - `--cnn-mixer v4`(v4 모터 할당기)로 이 비율이 20~23%로 줄었다. 현장에서도 코너가 좋아졌다.
2. **코너 직후 평행 회복이 늦다.** 맞은편 차선에 가까워져서야 바로잡는다.

근본 원인은 A5b의 학습 방식에 있다.

| 항목 | A5b (팀 코드 `train_policy.py` 확인) |
|---|---|
| 구조 | PilotNet. 입력 200×66 YUV(아래 절반, 3×3 흐림), 출력 [전진, 회전] ∈ [−1, 1] |
| 데이터 | Isaac Sim 합성 데이터만(`train-v5`, `train-v5-dart`, DART 흔들기 포함) |
| 정답 | 시뮬레이터 전문가가 **이상적인 차량**(출발 문턱 없음, 회전 효율 100%)에게 준 속도·회전 속도 |
| 제외 | 교차로 중심 35cm 안 |
| 증강 | 좌우 반전, 밝기 ±30%, 약한 색조, 잡음 |

- CNN이 말하는 "회전 속도"는 이상적인 차량 기준이다.
- 실제 차는 0.30 이상에서만 바퀴가 돌고, 회전은 명령의 약 62%만 일어난다. 게다가 팀 변환이 임의 계수(0.72)로 바퀴 명령을 만든다.
- 그래서 **출력과 실제 반응이 맞지 않고**, CNN이 화면을 보며 과하게 또는 모자라게 꺾어 맞춘다.

## 2. 무엇을 바꾸는가

- **정답 기준:** 실행 때 쓰는 출력 변환(v4 할당기) 기준으로 정답을 만든다. "이 [전진, 회전]을 내면 실제 차가 교사가 원한 곡률로 돈다"가 성립하게 한다.
- **차량 모델:** 출발 문턱, 회전 효율, 지연, 차량별 차이를 학습 데이터 수집에 넣는다.
- **카메라 교란:** 실차 기록에 맞춘 효과(`bench/realcam.py`: 반사·그림자·노출 지연·흐림·렌즈 주변부)를 넣는다.
- **DAgger:** 모델이 직접 운전하며 겪는 상황, 특히 코너 직후 비스듬한 상태에 정답을 붙여 학습한다.
- **바꾸지 않는 것:** 망 구조, 입력 전처리, 출력 형식은 A5b와 같다. 실행 코드(hyb2m, Pi 실행기)는 모델 파일만 바꿔 끼운다.

## 3. 단계

각 단계 끝의 "확인"을 통과하지 못하면 다음 단계로 가지 않는다.

| 단계 | 할 일 | 확인 | 예상 시간 |
|---|---|---|---|
| 0. 준비 | A5b ONNX 가중치를 팀 구조(PilotNet)의 PyTorch 모델로 옮긴다 | 같은 사진 수백 장에서 원래 A5b와 출력이 일치 | 30분 |
| 1. 교사 | 실제 위치를 아는 운전자를 만든다. 차선 중앙선 15~20cm 앞을 따라가며 곡률과 속도를 정하고, v4 할당기 기준으로 [전진, 회전] 정답을 역산한다 | 교사 혼자 차량 조건·카메라 교란에 관계없이 선을 안 밟고 깔끔하게 도는지 | 1시간 |
| 2. 1차 데이터 | 교사 주행을 기록한다. 시계·반시계, 외곽·안쪽 도로(교차로 중심 주변 제외), 차량 특성·카메라 효과 무작위, 일부러 흔들기(DART). 약 5만 장 | 정답 분포에 코너·복귀 상황이 충분한지 | 1시간 |
| 3. 1차 학습 | A5b 가중치에서 출발해 작은 학습률로 학습. 시뮬레이터 장면(seed)별로 학습·검증 분리 | 검증 데이터에서 교사와의 차이가 A5b보다 작은지(특히 코너·복귀) | 30분 |
| 4. DAgger | 모델이 시뮬레이터에서 직접 운전한다. 겪은 상황에 교사 정답을 붙여 더하고 다시 학습. 2~3회 반복 | 반복할수록 코너 후 평행 회복 시간, 선까지 여유가 좋아지는지 | 회당 1시간 |
| 5. 시뮬레이터 비교 | A5b(팀 변환) / A5b(v4) / A5b(dither) / 새 모델(v4). 지금까지의 시험 묶음(차량 여러 종, 실차 수준·harsh 카메라, 양방향, 교차로 포함 임무) | 거의 모든 조건에서 A5b 이상, 나빠지는 조건이 없는지 | 1시간 |
| 6. 실차 사진 점검 | 오늘 Pi에 저장된 실차 사진에 두 모델을 넣어 출력 비교(정답 없음) | 엉뚱한 출력이나 급변이 없는지, 코너 구간에서 어떻게 다른지 | 20분 |
| 7. 배포·실차 비교 | A5b와 같은 형식(ONNX)으로 내보내고 실행기에 모델 선택 옵션 추가. 실차에서 번갈아 비교 | 실차에서도 더 좋을 때만 기본값 교체. 아니면 A5b 유지 | 현장 |

**평가 지표** (5단계)
- 선 안 밟은 완주율
- 선까지 여유
- 코너 후 평행 회복 시간: 코너가 끝난 뒤 방향 오차가 5° 안으로 들어올 때까지
- 안쪽 바퀴가 섰다 돌았다 하는 비율

## 4. 위험과 대응

- **실제와의 차이:** bench는 평평한 바닥 질감에 배경 사진을 붙인 방식이라 Isaac Sim보다 입체감이 떨어진다. 6단계에서 실차 사진으로 먼저 걸러 낸다.
- **원래 데이터 없음:** Isaac Sim 원본 데이터는 여기 없다. 처음부터 학습하지 않고 A5b 가중치에서 작은 학습률로 출발해 잊어버림을 줄인다.
- **교차로:** 팀처럼 교차로 중심 주변은 학습에서 뺀다. 교차로는 지도와 제자리 회전이 맡는다(hyb2m).
- **심사 일정:** A5b는 예비로 남긴다. 새 모델은 시뮬레이터와 실차 모두에서 더 좋을 때만 쓴다.

## 5. 다음 대안 (B안)

CNN이 조향 명령 대신 **차선 안 위치와 방향**을 내고, 제어기가 조향을 계산하는 인식형 구조다.
- 코너 후 평행 회복 속도를 제어기 계수로 직접 조정할 수 있다.
- CNN과 지도가 같은 단위의 값을 내게 되어 교차 검증이 가능해진다. 곡률끼리 비교한 3안(hyb3)이 실패한 이유가 단위 불일치였다.
- 차량 특성이 바뀌어도 다시 학습할 필요가 없다.

새로 학습해야 하고 제어기도 만들어야 해서 A안보다 오래 걸린다. 심사 뒤나 A안의 효과가 부족할 때 진행한다.
