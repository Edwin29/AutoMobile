# hyb4 개발 시작점 — 2026-11-13

사용자가 `HYB4_SCOPE_PROPOSAL_20261113.md`의 권고 범위로 진행하도록 승인한 뒤 만든 별도 구현이다. **훈련된 hyb4 모델이나 완성된 bench/Pi 주행기는 아직 없다.** 기존 목표는 일시중지 상태를 유지한다.

## 이번에 구현한 것

- `control.py`: 촬영 시각이 붙은 차체 상대 경로/속도 계약, 부호 있는 좌우 PWM 할당, 실제 적용 PWM으로만 갱신하는 명목 응답 추정, 경로 추종기.
- `model.py`: PilotNet형 CNN → 투영 128 → GRU 64 → 48개 경로점 및 목표 속도 출력. 입력은 기존 YUV 영상, 직전 실제 PWM, 좌/직진/우 지시, 교차로 활성 여부, 프레임 시간 간격이다. 모델 초기값은 무작위이며 학습하지 않았다. A5b 초기화 여부·CNN 고정 범위·loss는 아직 결정/학습하지 않았다.
- `coordinator.py`: 일반 도로 제안과 교차로 경로 제어의 권한 분리, 기존 방향 resolver/원인별 stop·resume 재사용, 반복 상태 유지, 실제 PWM receipt. 기존 ROTATE/CREEP/SETTLE을 호출하지 않는다.
- `pilot.py`, `image_pilot.py`: 학습 전에 하위 제어와 기존 영상 추정의 성립 조건을 검사하는 고정 실험.

`Coordinator`는 외부 adapter가 영상 기반 지도 추정과 기존 일반 도로 출력을 제공해야 하는 연결부다. 일반 도로 정책을 새 정책으로 대체하지 않았으며, 제어권 전환의 부드러움·내부/외부 route 변경·비동기 지도 worker·실제 bench 등록은 미완료다. 기본 실행 목록에 hyb4를 추가하지 않았다.

실제 모터 적용은 이 모듈 밖의 단일 실행자가 수행한다. `propose()` 뒤 실제 PWM으로 `on_applied()`를 호출해야 한다. 제안 PWM과 실제 PWM이 다르면 실제 값만 다음 상태에 반영한다. 영상 정지·watchdog·외부 제한을 포함한 Pi 통합 시험을 통과했다는 뜻은 아니다.

할당기의 시간 평균 검사는 각 명령의 유지시간이 주어진 경우이며, 폐루프 실험은 고정 36ms 주기다. `Coordinator`는 다음 유지시간을 직전 간격으로 근사한다. 실제 추론 시간의 불규칙한 변화에 대한 듀티 적분 오차는 아직 검증하지 않았다.

## 사전 검증 결과와 중지 지점

새 개발 시드 25001/25002, 4개 회전, 3가지 차량 응답으로 각 24회를 실시했다. **정확한 경로/자세 입력 24/24 무이탈**, **기존 HSV 지도 추정 + 알려진 경로 21/24 무이탈**이다. 후자의 사전 기준은 22/24 이상이므로 통과하지 못했다. 학습 확대, 약한 복합/강한 교란 확대, 정책 채택을 보류한다.

결과는 [보고서](../cnn_finetune/results/hyb4_image_prerequisite_20261113/REPORT.md)를 참고한다. CNN 학습·CNN 폐루프 검증·전체 미션 완료와 구분한다. 제어기 preview 275ms는 이전 150~400ms 응답 범위의 중간값으로 고정했으며, 실제 차량 특성을 알아낸 값이 아니다.

## 재현

저장소 루트, 기존 Python 환경에서 실행한다.

```powershell
& D:\autodrive_cnn\venv\Scripts\python.exe -m unittest hyb4.test_control hyb4.test_coordinator -v
& D:\autodrive_cnn\venv\Scripts\python.exe -m hyb4.report
```

실험 protocol과 완료 파일은 이미 있으므로 `freeze`를 다시 실행하지 않는다. `run`은 완료 artifact가 있으면 다시 주행하지 않고 읽어 집계한다. `image_pilot.run`의 최초 집계에서는 메모리상의 tuple key와 JSON list key 비교가 실패했다. 24개 완료 파일을 다시 읽은 집계에서 초기값·사건의 일치를 확인했다. 고정 실험 소스와 protocol 해시는 보존하며, 후속 실험은 새 버전을 만든다.

## 남은 순서

1. 3건의 실패와 허용 가능한 관측·제어 오차 예산을 확인한다. 현재 결과만으로 새로운 인식 CNN이나 모터 특성 식별기를 필수로 선언하지 않는다.
2. 기존 FloorVO/지도 변화량과 새 FloorMotion의 역할·유효 관측을 동일 자료에서 비교한다. 이 비교는 아직 실행하지 않았다.
3. 경로 제어의 실패 기준을 해결한 뒤 작은 영상 경로 학습과 직접 PWM 기준선을 비교한다. 경로 자체의 오차, 곡률/속도, 차체 여유와 폐루프 복원을 함께 평가한다.
4. 접근→회전→출구→일반 도로 연결, 방향 예약/소비, stop·resume, 전체 미션을 검증한다.

노트북에서 회수한 자료는 저장소 밖 별도 폴더에 보관한다. 과거 문서의 날짜별 검토본과 현재 소스를 비교하기 전에는 예전 미해결 항목을 현재 결함으로 재분류하지 않는다.
